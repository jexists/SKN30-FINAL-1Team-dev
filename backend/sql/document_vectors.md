# 브리핑 관련 자료 RAG 적용

## 동작

- 자료요약 처리에서 기존 추출 원문을 청크로 나누고, 설정된 임베딩 모델로 변환해 `document_chunk.embedding_vector`와 모델 식별자를 저장한다. 요약문만 임베딩하는 방식이 아니다.
- 브리핑의 **제품 자료**는 딜 대표 제품 및 견적 품목에 연결된 자료다. 미팅에만 지정된 제품은 포함하지 않는다.
- **관련 자료**는 고객사·딜·제품 범위에서 키워드 검색과 pgvector 코사인 검색을 합쳐 상위 5개 청크를 선택한다. 팀·문서 열람권한·삭제 여부·완료된 최신 파일을 검사한다.
- 검색 결과와 제품 자료는 브리핑 입력 스냅샷에 저장된다. 화면은 해당 실행의 근거를 표시하며, 열람 시 현재 권한·삭제 여부를 다시 검사한다. 자료가 바뀌면 `briefing_refresh` 가 영향받는 미래 미팅의 브리핑을 백그라운드에서 다시 만든다 — 화면에는 수동 새로고침이 없다.
- `RAG 검색`은 관련 자료에만 표시된다. 키워드 전용이면 별도 안내하며 임베딩 장애 시 키워드 검색으로 대체한다. 검색 자체가 실패하면 성공 태그를 표시하지 않는다.

## 적용 순서

운영 DB에는 아직 적용하지 않았다. 대상 DB와 백업·확장 설치 권한을 확인한 뒤 다음 순서로 적용한다.

1. `20260912_0031_document_vectors.sql`을 먼저 실행한다. PostgreSQL에 pgvector 확장이 설치되어 있어야 한다. 이미 `extensions` 스키마에 설치했다면 마이그레이션 및 애플리케이션 연결의 `search_path`에 해당 스키마가 포함되는지 확인한다. HNSW 인덱스 생성은 쓰기를 차단할 수 있으므로 대용량 DB에서는 점검 시간에 진행한다.
2. 새 의존성을 설치하고 API와 워커에 동일한 임베딩 공급자·모델·차원을 설정한다. 현재 지원 차원은 384 또는 1536이다. 로컬 기본 모델은 384차원이며 로컬 모델 의존성은 기존 `local` 옵션을 사용한다 (`uv sync --extra local`). 다른 모델은 출력 차원을 반드시 확인한다.
3. 코드 배포 후 새 자료는 기존 자료요약 저장 과정에서 자동 색인된다. 임베딩 미설정·장애여도 원문과 요약은 저장된다.
4. 기존 자료는 아래 명령으로 대상 수를 확인한 다음 명시적으로 적용한다. 원문 추출·OCR·요약은 다시 실행하지 않는다. 외부 공급자를 선택하면 청크 본문이 그 공급자에게 전송되므로 자료 반출 허용 범위를 먼저 확인한다.

backend 디렉터리에서 실행한다. 실제 팀 UUID를 `<TEAM_UUID>` 자리에 넣는다.

```sh
uv run python -m scripts.backfill_document_vectors --team-id <TEAM_UUID>
uv run python -m scripts.backfill_document_vectors --team-id <TEAM_UUID> --apply --batch-size 32
```

기본은 조회만 수행한다. 적용 시 배치별 커밋하며 중단 후 재실행하면 현재 모델로 색인되지 않은 청크만 처리한다. 모델 변경 시에도 같은 명령으로 재색인한다. 다른 모델의 벡터는 검색에 섞지 않는다. 기존 JSONB 임베딩은 모델 식별자가 없어 자동 복사하지 않는다.

5. 백필이 끝나면 기존 브리핑은 그대로 남는다. 백필 자체는 `processed_at` 을 바꾸지 않아 source revision 도 그대로이므로, 갱신을 일으키지 않는다. 새 근거를 반영하려면 해당 자료를 다시 처리하거나(`POST /documents/process-batch`) 연결을 다시 저장해 revision 을 바꾼다.

`DOCUMENT_SEARCH_MIN_SIMILARITY=0.45`는 초기값이다. 실제 한국어 자료와 선택한 모델로 적합한 검색 결과를 평가한 뒤 조정한다. 로컬 테스트의 고정 벡터는 DB 검색의 정확성을 검증하며 실제 모델의 의미 검색 품질을 보장하지 않는다.

## 검증

- `tests/test_document_vectors.py`: 전용 로컬 PostgreSQL(127.0.0.1:55439, DB salesluv_rag_test)에만 실행 가능. 합성 벡터로 의미/키워드 결합, 차원·모델 분리, 타 팀·다른 구성원·삭제·이전 버전 제외, 장애 대체를 검사하고 롤백한다.
- `frontend/tests/briefingMaterials.browser.html`: 실제 RecordDrawer를 합성 API 응답으로 렌더링한다. 브리핑 하위 자료 영역, 태그, 페이지/발췌, 새로고침, 장애/이전 브리핑 호환을 검사한다. `VITE_API_BASE_URL`을 로컬 주소로 지정하고 Vite로 해당 경로를 열면 성공 시 제목이 `PASS`로 바뀐다. 운영 빌드에는 포함하지 않는다.

롤백 시 이전 코드를 먼저 복원한다. 기존 JSONB 열은 유지되어 있다. 새 벡터 열과 인덱스는 즉시 삭제할 필요가 없으며, 데이터 삭제는 별도로 검토한다.
