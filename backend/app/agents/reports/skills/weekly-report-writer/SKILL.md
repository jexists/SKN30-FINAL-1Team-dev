# 주간업무보고 작성

## 실행 시 자료 읽기

`read_report_context()`와 `read_report_sources()`로 서버가 고정한 주간 context와 모든 source unit을 읽습니다. 허용 근거는 선택된 해당 주 일일 불변 제출본인 `child_submission`과 참고 `attachment`입니다. 일일 아래의 미팅·원 STT, 다른 기간, 목록 설명이나 DB 원본을 추가 조회하지 않습니다.

이번 주 결과가 목표와 얼마나 달랐고 왜 그랬으며 다음 주에 무엇을 할지 보고합니다. 공통 작성 기준을 적용하고, 일일보고서를 이어 붙이거나 활동 목록으로 분석을 대신하지 않습니다. 다음 주 조치는 마지막 섹션에서 핵심어 중심의 Markdown 순서 없는 목록으로 씁니다.

## 작성 순서

**목표 → 실적 → 차이 → 원인 → 다음 주 조치** 순으로 씁니다.

1. **목표:** 해당 주에 정해진 목표와 지표·단위·대상 범위를 밝힙니다. 목표가 없으면 '주간 목표는 미확인입니다'라고 쓰고 실적이나 지난주 수치를 목표로 대신 쓰지 않습니다.
2. **실적:** 이번 주에 확인된 결과와 딜 상태 변화를 목표의 지표에 맞춰 정리합니다. 활동 건수는 활동 목표일 때 구분해 쓰며 계약·매출과 섞지 않습니다.
3. **차이:** 목표와 실적의 기간·단위·집계 범위가 같고 수치가 확인될 때만 차이를 계산합니다. 비교 기준이나 실적이 부족하면 '목표 대비 차이는 확인되지 않았습니다'처럼 밝힙니다. 정성 목표는 확인된 달성·미달 상태만 설명합니다.
4. **원인:** 차이를 설명하는 구체적인 고객 발언·조건·검증·지연 근거를 연결합니다. 미달이 있다는 이유만으로 영업 활동 부족이나 고객 무관심을 원인으로 추정하지 않습니다. 근거가 없으면 '차이의 원인은 미확인입니다'라고 쓰고, 가설이 제공됐으면 확인된 원인과 구분합니다.
5. **다음 주 조치:** 마지막 섹션에 확인된 원인·걸림돌에 대응하는 조치를 한 항목당 1건씩 핵심어 중심의 Markdown 순서 없는 목록으로 정리합니다. 제안과 이미 합의된 행동을 구분하고 담당자·기한·완료 기준과 선행조건의 누락을 표시합니다. 근거 없는 목표·약속이나 해결 효과를 새로 만들지 않습니다. 조치가 확인되지 않으면 '- 다음 주 조치 미확인'처럼 짧게 남깁니다.

## 기간과 딜 흐름

- 선택된 해당 주 일일보고서의 확정 제출 본문에서 같은 고객·딜의 변화를 날짜에 따라 연결합니다. 반복된 요청·검토·서명 언급은 여러 신규 계약으로 세지 않습니다.
- 반복 서술은 줄여도 고객 요구, 부정·조건, 보류·실주, 미완료 후속 조치는 남깁니다. 활동을 언급할 때는 확인된 방문·전화·온라인·이메일 방식을 구분하며, 없으면 방식 미확인으로 표시합니다.
- 기간 밖의 활동은 필요한 배경으로만 쓰고 이번 주 실적에 포함하지 않습니다. 날짜·집계 근거가 부족한 건수·금액·추이를 계산해 확정하지 않습니다.
- 일일보고서의 확정 제출 본문만 읽으며 그 아래 미팅 본문을 추가 조회하지 않습니다. 탐색 목록의 설명은 사실 근거가 아닙니다. 보고되지 않은 날의 활동이나 결과를 채우지 않습니다.

## 작성·검토 완료 기준

- 모든 필수 `source_id`에서 주간 목표·실적·차이·근거 있는 원인과 다음 주 조치가 필요한 만큼 반영됩니다.
- 목표와 실적의 기간·단위·집계 범위가 맞을 때만 비교하며, 같은 딜의 반복 언급을 여러 실적으로 세지 않습니다.
- 차이와 원인을 구분하고, 다음 주 조치는 확인된 원인·걸림돌에 대응하며 담당·기한·완료 기준의 실제 상태를 보존합니다.
