# 미팅보고서 작성

## 실행 시 자료 읽기

작성·수정자는 서버가 배정한 한 scope만 `read_meeting_evidence()`로 읽고, deal 배경이 적용될 때 정확한 `sales_deal_id`로 `read_deal_crm(sales_deal_id)`와 `read_previous_reports(sales_deal_id)`를 읽습니다. 검토자는 서버가 허용한 모든 scope와 각 deal에 허용된 같은 원자료를 읽습니다. 이전 보고서는 이번 미팅 전의 동결된 불변 제출본 최신 5건이며 배경일 뿐입니다. 공통·미지정 scope에 deal reader를 적용하거나 다른 딜, 더 오래된 DB 기록, 미팅 원 STT를 조회하지 않습니다.

미팅에 참석하지 않은 영업팀장·임원이 개별 미팅의 사실과 현재 딜 상태를 파악할 수 있게 씁니다. 공통 작성 기준을 적용하고, 대화 시간순 전사나 감상 대신 고객의 발언·요청·합의에 근거해 기록합니다.

## 작성 순서

딜별 본문은 **미팅 목적 → 논의 내용 → 고객 요구 → 합의사항 → 후속 조치** 순으로 연결합니다. 후속 조치를 제외한 필요한 항목은 Markdown **굵은 소제목**을 독립된 한 줄에 쓰고, 소제목 뒤 빈 줄에 합니다체 서술 문단을 씁니다. 마지막 후속 조치는 소제목 뒤 빈 줄에 핵심어 중심의 Markdown 순서 없는 목록으로 쓰며, 한 항목당 조치 1건만 담습니다. 짧은 사실 기록은 해당하는 소제목만 사용하며, 목적이 없으면 '미팅 목적은 미확인입니다'처럼 밝히고 결과나 추정 목적을 대신 넣지 않습니다. 본문이 정확히 '이번 미팅에서 구체적 논의 없음'인 경우에는 소제목을 붙이지 않습니다.

`unassigned_report`는 실제 딜 귀속이 불명확해 확인이 필요한 내용만 항목별 Markdown `- 내용` 목록으로 씁니다. 한 항목에는 한 내용만 담고, 다섯 고정 소제목·빈 placeholder·'없음' 반복을 만들지 않습니다. 근거가 없으면 `unassigned_report` 자체를 만들지 않습니다. 이 규칙은 `common_report`의 기존 사실별 bullet 규칙을 우선 재사용합니다.

`common_report`는 위 다섯 항목 서식을 사용하지 않습니다. 미팅 전체에 공통으로 해당하는 확인된 사실만 Markdown `- 내용` 목록으로 쓰고, 한 항목에는 한 사실이나 직접 연결된 논점만 담습니다. 확인된 담당자·기한은 같은 항목에 보존할 수 있습니다. 공통 근거에 없는 목적·요구·합의·후속 조치를 '미확인'으로 채우거나 특정 딜의 요구·금액·담당 내용을 옮기지 않습니다. 공통 근거가 없으면 작성 work unit 자체가 없으므로 내용을 만들지 않습니다.

1. **미팅 목적:** 만나거나 연락한 이유와 다룰 안건을 확인된 범위에서 밝힙니다. 활동 방식은 방문·전화·온라인·이메일을 구분하고, 없으면 미확인으로 남깁니다.
2. **논의 내용:** 실제 다룬 제품, 제안, 검증 결과, 가격·수량·조건과 남은 쟁점을 씁니다. 필요한 과거 배경은 이번 논의와 시점을 구분해 짧게 연결합니다.
3. **고객 요구:** 누가 무엇을 요청했고 어떤 조건·기한·예외를 붙였는지 보존합니다. 요구와 고객의 검토 의향을 구매 확정으로 바꾸지 않습니다.
4. **합의사항:** 양측이 실제 합의한 범위와 미합의·보류 사항을 구분합니다. 확인된 합의가 없으면 미확인 상태를 짧게 남기며, 요청을 합의로 바꾸지 않습니다.
5. **후속 조치:** 요청·제안·합의 여부를 구분하고 할 일, 담당자, 기한, 완료 기준과 선행조건을 밝힌 목록을 씁니다. 빠진 항목은 공통 기준대로 표시합니다. 후속 조치 자체가 없으면 '- 후속 조치 미확인'처럼 짧게 남기고 약속을 만들지 않습니다.

## 발언과 이전 약속

- '반응이 좋음', '성공적인 미팅', '계약이 유력함' 같은 근거 없는 감상·전망을 쓰지 않습니다. 담당자가 느낀 인상만 있으면 성과 판단에서 제외합니다. 구체적인 관찰·발언에 근거한 해석은 판단임을 구분하고, 고객이 쓴 긍정 표현도 고객 발언으로만 남깁니다.
- 제품을 확인한 일, 고객의 검토 발언, 담당자의 추정은 서로 다릅니다. '예산을 알아보겠다'를 '예산 확보', '일정이 맞으면'을 '도입 합의'로 바꾸지 않습니다.
- 이전 기록에서는 같은 딜의 이번 논의와 연결되는 약속·조건만 참고합니다. 당시 날짜가 확인되면 밝히되 없는 날짜를 만들거나 이전 기록을 전부 반복하지 않습니다.
- 이전에 요청한 자료를 이번에 전달했는지, 검증 약속이 이행되지 않았는지 등은 현재 근거가 있을 때만 연결합니다. 결과가 없으면 이행 여부 미확인으로 두며, 과거 논의를 이번 논의나 성과로 바꾸지 않습니다.
- 딜에 미치는 영향, 필요한 결정·지원은 근거가 있을 때 해당 논의나 후속 조치에 연결합니다. 정보 공유만 한 미팅에 승인·지원 요청을 새로 만들지 않습니다.

## 공통 내용과 딜별 내용

- 미팅은 회사 단위이며 딜은 그 안에서 다루는 개별 안건입니다. 회사·미팅 공통 맥락은 공통 본문의 사실별 목록에 한 번 작성하고 딜마다 복제하지 않습니다. 공통 방문 일정은 귀속 불명 내용과 다릅니다.
- 딜·공통·미지정 각 본문에는 실제로 그 범위에 속하는 자료와 필요한 미확인만 남깁니다. 다섯 항목을 근거 없이 채우거나 다른 범위의 사실을 복제하지 않고, 없는 사실·합의·후속 조치를 만들지 않습니다.
- 딜별 본문은 해당 딜의 현재 논의에 집중합니다. 공통으로 확인된 목적을 딜별 새 목적이나 성과로 확대하지 않습니다. 제목은 해당 딜에서 확인된 조건·결정·걸림돌을 짧게 드러내고 본문 순서를 대신하지 않습니다.
- 다른 딜의 이력이나 공통·미지정 발언을 특정 딜의 사실로 옮기지 않습니다. 미지정 내용도 별도 본문에 실제 발언·요청·부정·조건을 남기고, 어느 안건인지 불명확한 부분만 자연스럽게 밝힙니다. 내부 분류명이나 화면 제목을 본문에 되풀이하지 않습니다.
- 딜이 선택되지 않았어도 공통 내용과 미지정 내용의 근거는 보존합니다. 없는 딜을 만들거나 어느 쪽에도 속하지 않는다는 이유로 기록을 버리지 않습니다.
- 근거 없는 선택 딜의 '이번 미팅에서 구체적 논의 없음' 본문은 서버가 만듭니다. 작성자는 자료 누락·확인 불가·생성 실패를 이 문구로 대체하거나 과거 이력으로 빈 본문을 채우지 않으며, 검토·수정자는 서버 sentinel을 다른 내용으로 바꾸지 않습니다.

## 작성·검토 완료 기준

- 배정된 현재 `segment_id`의 핵심 발언·수치·부정·조건·후속 조치가 빠지지 않고 해당 scope에만 들어갑니다.
- 다른 딜·공통·미지정 사실이 섞이지 않으며, CRM과 최신 5건의 과거 내용이 이번 발언이나 현재 상태로 바뀌지 않습니다.
- 딜별·미지정 본문의 목적·논의·요구·합의·후속 조치 상태와 공통 사실 목록의 담당·기한이 원자료에 맞고, 서버 sentinel이 보존됩니다.

문장을 다듬어도 주체·시점·수치·딜 귀속, 발언과 판단의 구분, 부정·조건·예외를 유지합니다. 불확실성을 정확히 남긴 보고에 추측을 보태지 않습니다. 표현이 애매할 때는 [합성 작성 예시](references/examples.md)를 참고하되 예시의 사실이나 문단을 다른 보고서에 복사하지 않습니다.
