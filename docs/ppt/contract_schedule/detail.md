# 계약·일정 에이전트

영업현황을 바탕으로 미팅을 추천하고, 등록된 미팅의 준비용 브리핑을 제공합니다. 실행 순서는 서버가 제어하며, 일정은 사용자가 선택한 뒤 등록됩니다.

## 1. 에이전트별 역할

| 구분 | 계약관리 | 일정관리 |
| --- | --- | --- |
| 입력 | 영업현황, 위험 신호, 확정 보고서 | 미팅 조건, 담당자의 기존 일정 |
| 역할 | 미팅 필요성·이유 판단, 미팅 준비용 브리핑 생성 | 조건에 맞는 일정 후보 생성 |
| 출력 | 위험·누락 정보, 권장 행동, 미팅 제안·브리핑 | 일정 후보와 충돌 정보 |

추천만으로 계약·딜이 수정되거나 일정이 등록되지는 않습니다.

## 2. 자동 추천 흐름

**업무 변경 → 계약관리 판단 → 일정 후보 생성·검증 → 추천 저장 → 사용자 선택 → 일정 등록**

- 보고서 확정, 영업 건 생성·단계 이동, 딜 연결 일정 등록, CS 처리 시작 시 실행합니다.
- 같은 딜의 중복 실행을 확인합니다.
- 유효한 후보를 최대 5개 저장해 캘린더에 표시합니다. 제안·후보가 없거나 실행에 실패하면 추천 없이 끝날 수 있습니다.
- 일정 등록 후 브리핑 생성을 예약합니다. 수동으로 등록한 미팅도 대상입니다.

## 3. 판단과 검증

- **계약 위험:** 만료·납기, 장기 미접촉, 미해결 CS, 계약 정보 누락 등을 서버 규칙으로 확인합니다.
- **일정 조건:** 이미 지난 시각과 기존 일정에 겹치는 후보를 제외하고, 요청한 기간·소요 시간과 후보 중복 여부를 확인합니다.
- **사용자 선택:** 같은 추천의 중복 등록을 방지합니다. 등록 후 충돌은 경고하며, 등록 자체를 차단하는 방식은 아닙니다.
- **출력 검증:** Pydantic으로 AI 응답의 필수 항목, 데이터 형식, 허용된 값을 검사합니다.

## 4. 브리핑 검색·생성·갱신

### 검색과 생성

고객사·해당 딜·일정 정보를 검색어로 사용합니다. 열람 권한이 있는 최신 처리 완료 자료에서 키워드와 pgvector 벡터 검색 결과를 결합해 **상위 5개 청크(문서의 일부)**를 선택합니다. 임베딩을 사용할 수 없으면 키워드 검색만 수행합니다.

계약관리 에이전트는 일정·영업현황·위험 신호와 검색된 자료를 바탕으로 미팅 준비용 브리핑을 생성합니다. 출처 목록에는 실제로 조회한 자료만 남겨 사용자가 근거를 확인할 수 있도록 합니다. 검색 결과를 사용할 수 없는 경우에는 일정과 영업현황 등 확보된 정보를 바탕으로 브리핑을 제공합니다.

### 자동 갱신

**미팅 등록·수정 또는 자료·딜 정보 변경 → 대상 미팅의 갱신 예약 → worker 실행 → 새 브리핑 저장**

- 자료 처리 결과가 저장된 뒤 예약하며, 저장 요청은 브리핑 생성 완료를 기다리지 않습니다.
- 미팅 ID와 검색 대상 상태를 기준으로 중복 요청을 막습니다. 생성 중 자료가 바뀌면 후속 갱신을 예약합니다.
- 이전 자료로 만든 결과가 더 최신 자료의 결과를 덮지 않도록 합니다. 갱신 실패 시 마지막 성공 브리핑을 유지합니다.
- 미팅 상세 화면은 저장된 결과를 조회합니다. 갱신 중에도 기존 본문을 보여주고, 완료되면 새 결과로 교체합니다.

## 5. 제품 자료와 관련 자료

| 구분 | 제품 자료 | 관련 자료 |
| --- | --- | --- |
| 대상 | 딜 대표 상품·견적 품목의 연결 자료 | 딜·고객사·상품과 관련된 자료 |
| 조회 방식 | 연결 관계로 직접 조회 | 키워드 + 벡터 검색(RAG) |
| 개수 | 제한 없음 | 상위 5개 청크 |
| 표시 내용 | 파일명·저장 요약 | 페이지·발췌·RAG 검색 표시 |

브리핑 본문과 두 자료 목록은 같은 실행 결과로 저장·교체됩니다. 화면 조회 시 삭제 여부와 열람 권한을 다시 확인합니다. 제품 자료가 표시된다고 본문에 인용된 것은 아닙니다.

## 8. 데모 흐름

1. 가상 고객사·영업 건·기존 일정을 준비합니다.
2. 업무 변경으로 생성된 추천을 확인하고, 후보를 선택해 일정을 등록합니다.
3. 미팅 상세에서 브리핑과 제품 자료·관련 자료를 확인합니다.
4. 같은 딜에 자료를 추가하고, 처리 완료 후 브리핑과 근거가 함께 갱신되는지 확인합니다.
5. 권한 밖 자료가 노출되지 않는지 확인합니다.

시연 전 worker 실행, 자료 처리 완료, pgvector 마이그레이션 적용 여부와 운영 모델·임베딩 설정을 확인합니다.

## 9. 검증 현황

원본 문서에 기록된 브리핑 RAG·자동 갱신 브랜치의 검증 결과입니다. 이번 문서 정리에서 재실행한 결과는 아닙니다.

- 백엔드 1,467개 통과(10개 건너뜀), 프런트엔드 115개 통과. 빌드·린트·포맷 통과.
- 자동 갱신의 대상 선정, 중복 방지, 최신 결과 유지, 실패 처리, 권한 검사 등을 코드로 검증했습니다.
- 실제 DB를 사용하는 pgvector 통합 테스트는 실행하지 않았습니다.
- AI 답변의 정확성·미팅 유용성·출처 정확성·갱신 지연·비용은 별도 실환경 평가가 필요합니다.

테스트 통과 수치는 코드 검증 결과이며, AI 품질이나 운영 성능을 뜻하지 않습니다.
