# 대시보드 API 요구사항

> 상태: 프론트엔드 제안 원본(참고용)
> 최종 API 계약과 충돌하면 [SalesLuv API 공통 규약](api-conventions.md)을 따른다.

이 문서는 대시보드 화면에 필요한 **최소 데이터**만 정리한다. 실제 API 경로, 요청·응답 변수명, DTO 분리 방식은 백엔드 구현자가 정하고, 구현 후 FastAPI `/docs`를 최종 계약으로 사용한다.

## 1. 조회 기준과 권한

- 모든 업무 날짜는 `Asia/Seoul` 기준으로 계산한다.
- 팀원은 본인 데이터만 조회할 수 있다.
- 팀장은 본인과 같은 팀의 활성 팀원을 한 명, 여러 명 또는 팀 전체로 조회할 수 있다.
- 팀 전체에는 팀장 본인과 모든 활성 팀원이 포함된다.
- 요청한 사용자가 조회 범위를 임의로 넓힐 수 없도록 서버가 로그인 사용자와 팀 소속을 검증한다.
- 다른 조직이나 다른 팀 사용자의 데이터는 목록, 집계, 상세 어디에서도 노출하지 않는다.

## 2. 대시보드 조회 시 필요한 값

| 화면 영역 | 필요한 값 | 기준 |
|---|---|---|
| 공지 | 전체 공지 수, 최근 공지 내용 최소 3개 | 최신 게시 순. 전체가 3개 미만이면 있는 만큼 반환한다. 각 항목에는 상세 조회에 사용할 식별자가 필요하다. |
| 팀장 지시사항 | 전체 지시사항 수, 최근 지시 내용 최소 3개 | 최신 게시 순. 각 항목에는 식별자, 표시 내용, 게시 시각, 기한이 있으면 기한을 포함한다. |
| 오늘 방문 회사 | 오늘 방문 회사 수 | 같은 회사를 여러 번 방문해도 회사 수는 1개로 계산한다. 내부 업무는 제외한다. |
| 오늘 일정 | 오늘 전체 일정 수 | 오늘의 미팅과 내부 업무를 모두 포함한다. |
| 미완료 후속업무 | 미완료 전체 수, 지연 수, 7일 이내 마감 수 | 세 값은 동일한 담당자 범위와 기준 시각으로 계산한다. |
| C/S 대응요청 | 완료를 포함한 전체 수, 처리중 수, 전체 중 긴급 수 | 세 값은 같은 담당자 범위에서 계산하고 화면 카드와 상세 목록의 집계 기준을 맞춘다. |
| 계약갱신 예정 | 갱신 기준 일수, 기준일 이내 계약 수, 대표 회사, 나머지 회사 수 | 현재 화면 기준은 30일 이내다. `새봄정형외과 외 1곳` 같은 문장은 프론트에서 조합한다. |
| 매출 목표 | 목표 기간, 목표 금액, 현재 매출액, 달성률 | 달성률은 서버가 같은 금액 기준으로 계산한다. 목표가 없으면 달성률은 `null`로 구분한다. |
| 주간업무 | 조회 시작일·종료일, 날짜별 미팅 수, 날짜별 업무 수 | 화면에 보이는 7일을 반환한다. 날짜별 건수는 목록 페이지 크기와 관계없이 전체 건수다. |
| 오늘 미팅·업무 | 오늘 미팅 목록, 오늘 업무 목록과 각각의 전체 수 | 하나의 목록에 종류를 함께 주거나 두 목록으로 나누는 방식은 백엔드가 정한다. |

## 3. 미팅·업무 목록의 최소 항목

오늘 목록의 각 항목은 화면 표시와 상세·완료 처리에 필요한 아래 정보를 제공해야 한다.

- 항목 식별자
- 미팅 또는 업무 구분
- 시작·종료 시각
- 제목
- 완료 상태
- 영업 단계 또는 업무 상태가 있으면 해당 상태
- 회사, 고객 담당자, 장소가 있으면 해당 정보
- 한 줄 메모 또는 브리핑
- 연결된 보고서가 있으면 보고서 식별자와 작성 상태

## 4. 목록 조회 규칙

- 증가하는 모든 목록은 `skip`, `limit` 방식으로 조회한다.
- 기본값은 `skip=0`, `limit=30`이다.
- `limit`은 최대 30이며 30을 넘긴 요청은 자동 보정하지 않고 `422`로 거절한다.
- 다음 요청은 `skip=30&limit=30`, 그다음은 `skip=60&limit=30`처럼 조회한다.
- 목록 응답에는 항목 목록과 함께 전체 수, 현재 `skip`, 적용된 `limit`, 다음 데이터 존재 여부가 필요하다.
- 다음 데이터가 있으면 다음 요청에 사용할 `skip`도 함께 주는 것을 권장한다.
- 공지와 팀장 지시사항은 대시보드 첫 응답에 최소 3개를 포함하고, 추가 데이터는 같은 목록 조회 규칙으로 불러온다.
- 대시보드 카드의 숫자는 현재 내려준 최대 30건이 아니라 조건에 맞는 전체 데이터를 기준으로 계산한다.
- 정렬값이 같은 항목은 식별자를 보조 정렬값으로 사용해 순서를 고정한다.

목록 응답의 개념적인 형태는 다음과 같다. 정확한 변수명은 백엔드가 정한다.

```json
{
  "items": [],
  "skip": 0,
  "limit": 30,
  "total": 82,
  "has_more": true,
  "next_skip": 30
}
```

## 5. 담당자 선택 전달 방식

- 팀원은 별도 선택값 없이 본인 범위로 요청한다.
- 팀장은 조회할 사용자 식별자를 복수로 전달할 수 있어야 한다.
- 팀장이 사용자 식별자를 전달하지 않으면 팀 전체로 해석한다.
- 선택한 사용자 조건은 방문 회사, 일정, 후속업무, C/S, 계약갱신, 매출 목표, 날짜별 건수와 오늘 목록에 동일하게 적용한다.
- 공지와 팀장 지시사항은 팀 공개 범위이므로 선택한 담당자 조건과 분리한다.
- 알림은 로그인한 수신자 개인 데이터이므로 선택한 담당자 조건을 적용하지 않는다.

## 6. 대시보드 응답에서 제외할 것

- 안 읽은 알림 수와 알림 목록은 전역 상단 바에서 별도로 조회한다.
- 일정 한 건의 전체 상세, 계약·발주 상세 등은 사용자가 항목을 클릭했을 때 별도로 조회한다.
- 완료·미완료 변경과 일정 추가는 조회 응답에 포함하지 않고 별도 변경 API로 처리한다.
- 화면에서 조합할 수 있는 `3일 전`, `D-4`, `새봄정형외과 외 1곳` 같은 표시 문자열은 서버가 만들지 않는다.

## 7. 확인 기준

- 공지·지시사항의 전체 수와 실제 추가 조회 가능한 항목 수가 일치해야 한다.
- 데이터가 3개 이상이면 대시보드 첫 화면에 공지와 지시사항을 각각 최소 3개 표시할 수 있어야 한다.
- 카드 집계와 해당 카드를 눌러 확인하는 목록의 전체 수가 같은 조건에서 일치해야 한다.
- 같은 회사의 오늘 미팅이 여러 개여도 방문 회사 수는 한 번만 계산해야 한다.
- 선택한 날짜의 미팅·업무 수와 실제 목록의 전체 수가 일치해야 한다.
- 팀원, 팀장 단일 선택, 팀장 복수 선택, 팀 전체 권한을 각각 검증해야 한다.
- 금액은 원 단위 정수, 날짜는 `YYYY-MM-DD`, 일시는 `+09:00`을 포함한 ISO 8601로 반환한다.
