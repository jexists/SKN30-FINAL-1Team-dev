# 자료요약 Agent OCR 평가표

## 목적

[추론] OCR 결과가 실제 자료실 문서와 같은 의미를 보존하는지 확인하기 위한 평가표다.
문서 종류별 정답값을 먼저 기록하고, OCR 결과와 대조한다.

## 현재 합성 테스트 결과

| 입력 형식 | 테스트 내용 | 결과 | 확인 항목 |
|---|---|---|---|
| TXT | 합성 영업 문장 | 통과 | 텍스트·Markdown·페이지 |
| HTML | 제목·본문 | 통과 | 태그 제거·텍스트·페이지 |
| DOCX | 문단·표 | 통과 | 표 행·Markdown·페이지 |
| PPTX | 슬라이드 텍스트 | 통과 | 슬라이드·Markdown·페이지 |
| 스캔 PDF | 합성 이미지 PDF | 통과 | Runpod OCR·Markdown·페이지 |

[검증] 위 결과는 개인정보 없는 합성 파일에서 실행한 구조 검증 결과이며, 실제 문서의
한글·표·금액 인식 정확도를 의미하지 않는다.

## 실제 샘플 구조 테스트 결과

[검증] 2026-08-29에 프로젝트의 비식별화 샘플 5개를 외부 LLM 없이 로컬 추출·OCR로
실행했다. 모든 파일에서 텍스트와 Markdown이 생성됐고, 페이지 번호가 1부터 순서대로
생성됐으며, 비어 있지 않은 RAG 청크가 만들어졌다.

| 파일 형식 | 처리 경로 | 페이지 | 결과 | 의미 |
|---|---|---:|---|---|
| PDF | pdf-inspector | 2 | 통과 | 텍스트 PDF 추출·페이지 보존 |
| PDF | pdf-inspector | 2 | 통과 | 텍스트 PDF 추출·페이지 보존 |
| PDF | pdf-inspector | 3 | 통과 | 다중 페이지 추출·페이지 보존 |
| PDF | pdf-inspector + local OCR | 1 | 통과 | 스캔 PDF 로컬 OCR fallback |
| DOCX | DOCX parser | 1 | 통과 | 문단·표 추출 |

[미확인] 위 테스트는 구조와 결과 생성 여부를 확인한 것이며, 정답 원문 대조가 없어
한글·금액·날짜·당사자 필드의 필드 정확도는 아직 계산하지 않았다.

[검증] 사용자가 제공한 실제 명함 이미지는 저장소 샘플 디렉터리 밖의 별도 경로에서
실행했으며, 결과는 아래에 개인정보 없이 집계했다.

## 실제 명함 정답표 적용 결과

[검증] 2026-08-29에 제공된 실제 명함을 정답표와 비교했다. 명함 원문과 개인정보는
저장소에 기록하지 않고 일치 여부와 집계 결과만 남긴다.

| 단계 | 비교 필드 수 | 일치 | 정확도 | 결과 |
|---|---:|---:|---:|---|
| 로컬 OCR 원문 | 7 | 7 | 100% | 통과 |
| 고객 등록용 구조화 | 6 | 6 | 100% | 통과 |
| 필수 등록값(name·company·phone) | 3 | 3 | 100% | 누락 없음 |

[검증] 로컬 PaddleOCR 명함 프로필과 설정된 OpenAI 구조화 Agent를 순서대로 실행했고,
구조화 결과는 고객 등록에 필요한 필수값을 모두 포함했다.

[추론] 이번 결과는 한 장의 명함에 대한 검증이므로 전체 명함 품질을 대표하지 않는다.
다른 촬영 각도·배경·해상도·한글 글꼴의 명함을 추가해 같은 정답표 방식으로 평가해야 한다.

## 실제 취업규칙 PDF 정답표 및 테스트 결과

[검증] 제공된 취업규칙 PDF의 표지와 목차를 사람이 확인해 아래 값을 정답표로
사용했다. 원문 전체는 저장소에 복사하지 않고, 평가에 필요한 기준값과 집계 결과만 기록한다.

### 정답표(사람이 확인한 전체 후보 필드)

| 필드 | 정답값 | 페이지 |
|---|---|---:|
| 문서명 | 취업규칙 | 1 |
| 회사명 | 주식회사 메디메디 | 1 |
| 전체 페이지 수 | 35 | 전체 |
| 버전 1.0 | 2024.01.02 / 신규 제정 | 1 |
| 버전 2.0 | 2025.02.23 / 2025년도 노동법 개정에 따른 취업규칙 개정 | 1 |

| 장 | 정답 제목 |
|---:|---|
| 1 | 총칙 |
| 2 | 채용 및 근로계약 |
| 3 | 복무 |
| 4 | 인사 |
| 5 | 근로조건 |
| 6 | 임금 |
| 7 | 정년·퇴직·해고 등 |
| 8 | 퇴직급여 및 표창·징계 |
| 9 | 교육 및 성희롱의 예방 |
| 10 | 직장 내 괴롭힘 예방 |
| 11 | 안전보건 |
| 12 | 재해보상 |

### 테스트 결과

[검증] 2026-08-29에 로컬 `pdf-inspector`와 로컬 OCR fallback으로 PDF를 처리했다.
페이지 번호는 1부터 35까지 순서대로 생성됐고, 텍스트·Markdown·RAG 청크가 생성됐다.

| 평가 항목 | 비교 수 | 일치 | 정확도 | 결과 |
|---|---:|---:|---:|---|
| 문서 기본정보·버전·일자·개정사유 | 6 | 6 | 100% | 통과 |
| 12개 장 제목 | 12 | 12 | 100% | 통과 |
| 페이지 구조 | 35 | 35 | 100% | 통과 |
| 비어 있지 않은 RAG 청크 | 166 | 166 | 해당 없음 | 통과 |

[추론] OCR 결과의 제목은 `제 장 총 칙1`처럼 번호가 제목 뒤로 이동하는 레이아웃
순서 오류가 일부 있었지만, 장 번호와 제목을 분리해 비교하면 의미는 보존됐다.

[미확인] 조문 본문 전체의 글자 단위 정확도, 법률 용어·숫자·기간 값의 완전 일치는
별도 조문 대조표가 있어야 계산할 수 있다.

## 실제 사업자등록증 이미지 정답표 및 테스트 결과

[검증] 2026-08-29에 사용자가 제공한 1페이지 사업자등록증 이미지에서 사람이 확인한
필드를 정답표로 만들고, 저장소 밖의 원본을 로컬 OCR에 입력했다. 원본의 등록번호·주소·
대표자명은 개인정보 보호를 위해 저장소에 기록하지 않고, 아래에는 비교 범위만 남긴다.

### 정답표

| 필드 | 정답 기준 |
|---|---|
| 문서명 | 사업자등록증 |
| 문서 유형 | 법인사업자 |
| 등록번호 | 첨부 원문과 일치하는 3-2-5 숫자 형식 |
| 법인등록번호 | 첨부 원문과 일치하는 6-7 숫자 형식 |
| 법인명 | `(주) 인트로메딕` |
| 대표자 | 첨부 원문과 일치하는 성명 |
| 개업연월일 | 2004년 09월 11일 |
| 사업장·본점 소재지 | 서울특별시 구로구 디지털로31길 41, 1105호를 포함한 원문 |
| 업태 | 제조, 도매 |
| 종목 | 의료기기, 무역 |
| 발급사유 | 정정 |
| 발급일 | 2017년 04월 05일 |
| 부가가치세 과세 적용 | 부 선택 |
| 전자세금계산서 전용 전자우편주소 | 공란 |

[검증] 자동 점수에는 문서명·문서 유형·등록번호·법인등록번호·법인명·대표자·개업연월일·
주소·호수·업태 2개·종목 2개·발급사유·발급일의 15개 필드를 사용했다. 부가가치세 과세
적용 여부와 전자우편주소는 정답표에는 기록했지만 이번 자동 점수에는 포함하지 않았다.

### 테스트 결과

[검증] 로컬 `PaddleOCR` 문서 프로필로 이미지 1장을 처리하고, 공백·하이픈·괄호를
제거한 뒤 15개 기준 필드의 포함 여부를 비교했다.

| 평가 항목 | 비교 수 | 일치 | 정확도 | 결과 |
|---|---:|---:|---:|---|
| 사업자등록증 핵심 필드 | 15 | 12 | 80% | 부분 통과 |
| 페이지 수 | 1 | 1 | 100% | 통과 |
| OCR 결과 생성 | 1 | 1 | 100% | 통과 |

| 일치한 필드 | 문서명·문서 유형·등록번호·대표자·주소·호수·업태·종목·발급사유·발급일 |
|---|---|
| 불일치한 필드 | 법인등록번호·법인명·개업연월일 |

[추론] 이번 수치는 한 장의 사진에서 15개 필드를 정규화한 포함 여부를 계산한 값이므로,
문서 전체 글자 단위 정확도나 다른 촬영 환경의 성능을 의미하지 않는다.

[미완료] 법인등록번호·법인명·개업연월일은 자동 승인 대상에서 제외하고 사용자 검토로
보내야 한다. 다음 개선은 해당 영역의 ROI 재인식과 숫자·날짜 형식 검증을 추가하는 것이다.

## 승인·RAG 저장 재검증 결과

[검증] 2026-08-29에 개인정보 없는 합성 문서 1건으로 실제 자료실 저장 흐름을 재검증했다.
파일 업로드 후 `review_required` 상태에서 추출 결과와 요약 초안이 생성됐고, 승인 전 RAG
검색은 0건이었다. 승인 후에는 `completed` 상태로 바뀌고 청크·임베딩·페이지 메타데이터가
생성되어 RAG 검색 결과가 반환됐다. 테스트 데이터와 Storage 객체는 종료 과정에서 삭제됐다.

| 검증 항목 | 결과 |
|---|---|
| 승인 전 요약 초안 | 통과 |
| 승인 전 RAG 제외 | 통과 |
| 승인 후 완료 상태 전환 | 통과 |
| 승인 후 청크·임베딩 생성 | 통과 |
| 승인 후 페이지 메타데이터 보존 | 통과 |
| 합성 테스트 데이터 정리 | 통과 |

[검증] 같은 날 원격 Supabase를 읽기 전용으로 집계한 결과, 완료 파일 233건과 완료 RAG
청크 233건이 확인됐고, 233건 모두 페이지 참조·출처 메타데이터·임베딩을 가지고 있었다.
이 값은 검증 시점의 데이터 집계이며 운영 중 변할 수 있다.

## 판정 기준

[가정] 프로젝트에서 정한 통과 기준을 아래 빈칸에 입력한다.

```text
필드 정확도 = 정확하게 인식된 필드 수 ÷ 정답이 있는 전체 필드 수
문서 통과 기준 = __________
핵심 필드 최소 기준 = __________
```

[추론] 금액·날짜·기간·당사자 중 하나라도 틀리면 문서 전체를 자동 승인하지 않고,
사용자 검토 대상으로 남기는 것이 안전하다.

## 실행 명령

합성 E2E는 외부 전송되는 개인정보 없이 다음 명령으로 재검증한다.

```bash
cd backend
DEBUG=false .venv/bin/python scripts/document_rag_e2e.py --run
```

실제 문서는 개인정보 제거 및 외부 API 전송 허용 여부를 확인한 뒤 별도 평가한다.
