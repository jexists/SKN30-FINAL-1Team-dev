# 자료요약 Agent 정확도 평가 계획

## 목적

OCR·문서 추출·요약·RAG를 한 번에 “정확하다”고 판단하지 않고, 단계별 정답과 실패 기준을
분리해 기록한다. [추론] 단계별 오류를 분리해야 OCR 오류와 요약 오류를 혼동하지 않고
수정 우선순위를 정할 수 있다.

## 현재 확인된 품질

| 단계 | 현재 확인 | 판정 |
|---|---|---|
| PDF·DOCX 추출 | PDF 4건·DOCX 1건에서 텍스트와 Markdown 생성 | [검증] 구조 통과 |
| 페이지 보존 | 샘플 문서 페이지 번호가 1부터 순서대로 생성 | [검증] 통과 |
| RAG 청크 | 샘플 문서에서 비어 있지 않은 청크 생성 | [검증] 통과 |
| 결과 파일 | `text`, `txt`, `md`, `json` 경로 제공 | [검증] API 테스트 통과 |
| 로컬 명함 OCR | 실제 고해상도 이미지가 Mobile 모델 적용 후 smoke test 통과 | [검증] 런타임 통과 |
| OpenAI 구조화 요약 | 개인정보 없는 합성 입력의 스키마 검증 통과 | [검증] 통합 테스트 통과 |
| 필드별 OCR 정확도 | 필드 정답지 없음 | [미완료] 수치 산출 불가 |
| 요약 사실성 | 사람 검수 정답지 없음 | [미완료] 수치 산출 불가 |
| RAG 검색 정확도 | 질의별 정답 청크 목록 없음 | [미완료] 수치 산출 불가 |

## 평가 데이터 준비

[가정] 팀에서 외부 공유가 허용된 개인정보 없는 문서 세트와 명함 이미지 세트를 준비한다.
실제 고객 정보가 들어간 원본은 저장소·로그·평가 결과에 포함하지 않는다.

문서별로 다음 정답 파일을 별도 보관한다.

```text
문서 ID
원본 형식
페이지 수
핵심 필드 정답
필드별 허용 표기
정답 요약
질의별 정답 청크 ID
```

## 단계별 측정

### 1. OCR·추출

- 필드 정확도 = 정확히 일치한 필드 수 / 평가 대상 필드 수
- 필드별로 이름, 회사명, 직책, 전화번호, 이메일을 따로 계산한다.
- 전화번호·이메일은 공백·하이픈 등 정규화 규칙을 먼저 고정한다.
- 페이지 정확도는 원본 페이지 수와 결과 `page_count`를 비교한다.
- 실패 판정: 필수 필드가 비어 있거나 페이지 수가 달라지면 해당 문서는 실패로 기록한다.

### 2. 요약

사람 검수자가 다음 항목을 `통과/수정 필요/근거 없음`으로 판정한다.

- 핵심 내용이 원문에 존재하는가
- 금액·기간·날짜가 원문과 같은가
- 요약에 없는 사실을 추가하지 않았는가
- 불확실한 내용이 확인 필요 항목으로 남았는가

[미확인] 검수자 수와 합의 방식은 팀에서 정해야 한다. 이 값이 정해지기 전에는 요약
정확도 백분율을 산출하지 않는다.

### 3. RAG

질의별로 정답 청크를 먼저 표시한 뒤 다음 식으로 계산한다.

```text
검색 재현율 = 검색된 정답 청크 수 / 전체 정답 청크 수
검색 정밀도 = 검색된 정답 청크 수 / 전체 검색 청크 수
```

페이지 출처가 있는 경우 청크 내용뿐 아니라 `page_start`, `page_end`, `document_id`도
정답과 일치하는지 확인한다.

## 실행 명령

구조 품질과 페이지·청크 생성은 개인정보 없는 샘플로 실행한다.

```bash
cd backend
OCR_PROVIDER=local ./.venv/bin/python scripts/document_quality_smoke.py \
  --ocr-local ../data/sanitized_docs
```

OpenAI 통합 테스트는 외부 전송과 비용을 인지한 경우에만 실행한다.

```bash
RUN_INTEGRATION_TESTS=true ./.venv/bin/pytest -q \
  tests/test_contract_schedule_pipeline.py::test_contract_schedule_briefing_pipeline_with_real_llm
```

## 폐기·재평가 기준

- [가정] 필수 OCR 필드 실패가 팀이 정한 허용 수준을 넘으면 해당 전처리·모델 조합을 폐기한다.
- 금액·계약기간·날짜의 오인식이 발견되면 전체 평균으로 상쇄하지 않고 해당 문서 유형을
  별도 재평가한다.
- RAG 검색은 정답 청크를 반복해서 놓치거나 잘못된 계약 문서를 상위에 올리면 청킹·임베딩·
  메타데이터 필터를 재검토한다.
