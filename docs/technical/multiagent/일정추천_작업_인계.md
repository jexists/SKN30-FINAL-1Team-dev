## 사용자 요구사항

다음 세 문제를 해결하는 작업이다.

1. 추천 거절 시 에러가 발생한다.
2. 최신 미팅 보고서에 `9월 22일 4시 만남 예정`이 있는데 과거 추천인 `9월 16일`이 계속 표시된다.
3. 추천 카드의 `시작시간 (선택)` UI를 삭제한다.

추가로 합의한 동작은 다음과 같다.

| 상황 | 기대 동작 |
|---|---|
| 새 보고서 확정, 실행 중인 추천 없음 | 즉시 최신 보고서 기준 추천 작업 예약 |
| 새 보고서 확정, 같은 딜 추천 실행 중 | 현재 실행은 끝내고 가장 최신 보고서 1건만 후속 실행 |
| 여러 보고서가 실행 중 연속 확정됨 | 중간 요청은 취소하고 최신 요청 1건만 보존 |
| 같은 추천을 사용자가 다시 생성 | 확인 모달을 보여준 뒤 사용자가 승인하면 재실행 |
| 화면 새로고침/네트워크 중복 요청 | 사용자 확인 모달을 띄우지 않음 |
| 추천 생성 중 | `AI 추천 일정 생성 중…` 표시 |
| 최신 보고서가 후속 대기 중 | `최신 보고서 반영 중…` 표시 |
| 추천 거절 | 기존 카드를 숨기고 재추천을 DB 작업으로 예약; HTTP 요청에서 LLM 완료를 기다리지 않음 |

## 확인된 원인

### 최신 보고서가 반영되지 않은 원인

- `2026-09-15 10:19`에 같은 딀에 대해 `2026-09-16 14:00` 추천이 생성됐다.
- `2026-09-15 10:23` 새 보고서에는 `9월 22일 4시`가 정확히 저장됐다.
- 기존 구현은 동일 딜의 완료 실행을 10분 동안 막아 새 보고서용 AgentRun 자체를 생성하지 않았다.
- 결과적으로 최신 보고서를 읽지 않고 과거 추천 카드가 그대로 표시됐다.

### 거절 오류 원인

- 거절 API가 HTTP 요청 안에서 `regenerate()`를 호출해 LLM 2단계를 동기 실행했다.
- 입력 구성, LLM 출력, 날짜 검증 중 하나라도 실패하면 `False`만 반환하고 API는 `503 recommendation_refresh_failed`를 반환했다.
- 일부 실패 경로는 상세 로그가 없어 화면에서는 이유를 알 수 없었다.

## 이전 단계에서 완료된 기반 작업

다음 작업은 이미 구현되어 있었고 관련 테스트가 통과한 상태였다.

- 추천 1·2단계를 DB `agent_run` 영속 작업으로 실행하는 worker 연결
- 서버 재시작 후 `queued/running` 작업 복구
- worker lease와 heartbeat를 이용한 재시도
- `schedule_management` 완료 후 추천 카드 upsert
- `scripts/dev.sh` 실행 시 Agent worker도 함께 시작
- 추가된 개발 worker 스크립트: `scripts/agent-worker.sh`

이 기반 작업을 검증했을 때:

- 관련 테스트 211개 통과
- 별도 핵심 테스트 93개 통과
- Ruff 및 worker DB 스키마 검사 통과

## 이번 턴에 적용된 변경

## 화면 수동 검증 시나리오

### 최신 보고서 우선 반영

1. 동일 딜에 기존 추천 카드가 있는 상태에서 새 미팅 보고서를 작성한다.
2. 보고서에 미래 날짜와 시각을 명확히 입력한다. 예: `2026년 9월 22일 오후 4시에 만나기로 합의`.
3. 보고서를 확정한다.
4. 캘린더에서 `AI 추천 일정 생성 중…`을 확인한다.
5. 실행 중 새 보고서를 하나 더 확정하면 `최신 보고서 반영 중…`을 확인한다.
6. 완료 후 가장 최신 보고서의 날짜가 카드에 표시되는지 확인한다.

### 추천 거절

1. 추천 카드에서 `추천 거절`을 누른다.
2. 카드가 즉시 목록에서 사라지는지 확인한다.
3. 생성 중 문구가 표시되는지 확인한다.
4. 새 추천이 이전 날짜를 제외한 날짜로 생성되는지 확인한다.
5. 서버를 중간에 껐다 켜도 worker가 작업을 이어가는지 확인한다.

### 수동 다시 추천

1. 추천 카드에서 `다시 추천`을 누른다.
2. 확인 모달에서 `취소` 시 요청이 발생하지 않는지 확인한다.
3. 다시 열고 `다시 생성`을 누른다.
4. 생성 상태 문구와 최종 갱신 결과를 확인한다.

### 시작시간 UI 제거

1. 추천 카드에 `시작시간 (선택)` 입력이 없는지 확인한다.
2. 보고서에 합의 시각이 포함된 추천은 해당 시각을 서버 값으로 사용해 일정 등록되는지 확인한다.
3. 합의 시각이 없는 추천은 날짜와 소요시간만 승인되는지 확인한다.

## 데이터 변경 주의

- 진단 과정에서 운영성 테스트 DB의 기존 상태를 조회했으며, 이번 최신 요청 처리에서는 직접 SQL로 데이터를 수정하지 않았다.
