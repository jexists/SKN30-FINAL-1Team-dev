# 한 줄로

> **"이 미팅 몇 분 잡을까?"를 AI가 정하고, 서버가 그 길이를 지키게 합니다.**

---

# 1. 소요 시간이 뭔가요

카드에 이런 문장이 뜹니다.

```
"○○병원을    다음 주 화요일 오전에    60분    만나세요"
              └──────────────┘      └──┘
                  언제 (일정관리)      얼마나 ← 이 문서
```

**헷갈리기 쉬운 것 하나.**

| 말 | 뜻 | 예 |
|---|---|---|
| **선호 기간** | 시간을 **찾아볼 범위** | "9월 1일 ~ 9월 10일 사이에서" |
| **소요 시간** | 실제 **회의 길이** | "60분짜리를 찾아라" |

둘은 다른 값입니다. 선호 기간은 넓을수록 좋고(고를 게 많아짐), 소요 시간은 정확할수록
좋습니다.

---

# 2. 누가 정하나 — 3단계

```
① 서버가 재료를 모은다        "45일 연락 없음", "견적 3일 남음"
        ↓                     ← 뺄셈이라 틀릴 수 없음
② AI가 숫자를 정한다           "90분"
        ↓                     ← 판단이라 정답이 없음
③ 서버가 그 길이를 강제한다     후보를 전부 정확히 90분으로 맞춤
                              ← 달력 보면 되니까 다시 검사함
```

**①과 ③은 코드, ②만 AI입니다.**

이 프로젝트 전체가 쓰는 원칙과 같습니다 — **"뺄셈은 서버가, 판단은 AI가."**

---

# 3. 왜 시간까지 코드로 안 정했나요

`if 견적만료 then 30분` 같은 표를 만들면 될 것 같은데, 안 만들었습니다.
**이유는 하나입니다.**

```
같은 "견적 만료 3일 전" 딜인데

  A딜  "서명만 남았습니다"              →  30분이면 충분
  B딜  "가격을 처음부터 다시 협상"       →  90분도 빠듯
```

딜 데이터만 보면 **A와 B가 똑같이 생겼습니다.** 위험 신호도 같고 단계도 같습니다.
다른 건 **"만나서 무슨 얘기를 할 거냐"** 하나뿐입니다.

그건 데이터가 아니라 **글(안건)** 에 있습니다. 그래서 그 글을 쓴 AI가 같이 정합니다.

---

# 4. AI가 보는 것 두 가지

## ① 안건 — 가장 중요합니다

AI가 직접 쓴 "왜 만나야 하는지"(`reason`)를 보고 정합니다.

| 안건이 이러면 | 이만큼 |
|---|---:|
| 확인·서명만 하면 되는 일 | **30분** |
| 보통 상담·협의 | **60분** |
| 요구사항 정리, 따질 게 여럿 | **90분 이상** |
| 오래 끊겼다가 다시 만남 | **60~90분** |

이 표는 코드가 아니라 **AI에게 주는 지시문**에 들어 있습니다.
(`backend/app/agents/contract_management.py`)

## ② 딱지와 간격 — 참고 재료입니다

서버가 딜을 훑어서 붙여 주는 정보입니다. 5장·6장에서 봅니다.

---

# 5. "딱지"(태그)가 어떻게 반영되나

서버가 딜을 보고 **위험 딱지 7개** 중 해당하는 걸 붙입니다. 이건 규칙이라 정확합니다.

```
계약 만료 30일 남음   →  🏷 contract_expiring
미해결 C/S 있음       →  🏷 unresolved_support
45일 연락 없음        →  🏷 follow_up_overdue
```

**딱지는 시간에 대해 이런 느낌을 줍니다.**

| 딱지 | 무슨 뜻 | 시간은? |
|---|---|---|
| 견적 만료 임박 | 곧 견적이 죽는다 | 보통 **짧다** (수락만 확인) |
| 계약 만료 임박 | 곧 계약이 끝난다 | 보통 **짧다** (갱신 의사 확인) |
| 계약 정보 없음 | 계약번호·금액이 빔 | **짧다** (빈칸 채우기) |
| 납품 지연 | 납품일이 지났다 | **중간~길다** (설명이 붙음) |
| 계약 후 점검 | 체결하고 1~2주 지남 | **중간** |
| 오래 연락 없음 | 30일 넘게 안 만남 | **길다** (6장) |
| 미해결 C/S | 불만이 안 풀렸다 | **길다** (따질 게 많음) |

## ⚠️ 여기가 제일 헷갈리는 부분입니다

**이 표는 코드에 없습니다.** 어디에도 `견적만료 = 30분` 이라고 적혀 있지 않습니다.

```
서버가 하는 일:   딱지를 붙여서 AI에게 넘긴다.        ← 여기까지만
AI가 하는 일:     딱지 + 안건을 같이 보고 분을 정한다.  ← 숫자는 여기서 나옴
```

위 표는 **"대체로 이런 경향이 나온다"** 는 설명이지, 시스템이 따르는 규칙이 아닙니다.

**왜 규칙으로 안 박았냐면** — 3장의 A딜/B딜 때문입니다. 딱지로 분을 정하면 A도 B도 30분이
나옵니다.

## 급한 것 ≠ 긴 것

딱지에는 **심각도**(높음/보통)도 붙습니다. 이건 **시간이 아니라 급한 정도**에 씁니다.

```
심각도 높음  →  "이번 주 안에 만나라"   (언제)
             →  길이와는 상관없다      (얼마나)
```

오히려 급한 건은 확인 하나만 하는 경우가 많아서 **짧습니다.**

---

# 6. "고객 간격"이 어떻게 반영되나

간격은 **며칠 만에 만나는가**입니다. 두 종류가 있고, 둘 다 서버가 계산합니다.

## ① 마지막으로 만난 지 며칠

```
마지막 활동 날짜부터 오늘까지 세다  →  45일
                                    ↓
                    30일 넘었나?  →  YES  →  🏷 오래 연락 없음
                                             + "45일" 이라고 숫자도 같이 보냄
```

> 활동 기록이 아예 없는 딜은 **딜을 만든 날**부터 셉니다.
> 안 그러면 오늘 만든 딜이 바로 "오래 연락 없음"으로 잡힙니다.

## ② 계약서에 도장 찍은 지 며칠

```
7일 지남   →  🏷 계약 후 점검 (보통)
14일 지남  →  🏷 계약 후 점검 (높음)
```

## 이게 분(分)으로 바뀌는 길

```
[서버]  45일이라고 세서 넘김
   ↓
[AI]    "45일이나 끊겼네. 그동안 뭐가 바뀌었는지 다시 들어야겠다"
   ↓
[AI]    안건이랑 같이 봐서  →  90분
```

지시문에 이 한 문장이 들어 있습니다:

> *"오래 끊겼다가 다시 만나는 자리는 상황을 다시 듣는 시간이 필요하므로 60~90분으로 잡는다."*

## 왜 "30일=60분, 90일=90분" 표를 안 만들었나

만들 수는 있는데, **그 숫자의 근거가 없습니다.**

간격이 길수록 시간이 더 든다는 건 맞습니다. 그런데 **정확히 며칠부터 15분이 더 필요한지는
아무도 모릅니다.** 그냥 정하면 그럴듯한 거짓말이 코드에 박힙니다.

그래서 **실제 일수를 그대로 넘기고** AI가 안건과 같이 보게 뒀습니다.
45일과 200일은 같은 딱지지만 다른 숫자로 도착합니다.

## 지금 안 되는 것 4가지

| 구멍 | 무슨 일이 생기나 |
|---|---|
| **29일은 아무 신호가 없다** | 25일 만에 만나도 딱지가 안 붙어서, AI는 얼마 만인지 아예 모릅니다 |
| **계약 후 점검은 날짜만 준다** | "45일" 대신 "8월 20일 체결"을 줘서, AI가 직접 빼야 합니다. 형식만 맞추면 되는 일입니다 |
| **30초 통화도 접촉으로 친다** | 두 시간 방문과 똑같이 간격이 0으로 초기화됩니다 |
| **딜 단위로 센다** | 같은 병원을 지난주에 다른 딜로 만났어도, 이 딜에 기록이 없으면 "오래 끊김"입니다 |

# 7. 서버가 마지막에 하는 일 — 길이 맞추기

AI에게 "60분"이라고 시켰는데 **30분짜리 후보를 낼 때가 있습니다.**
그냥 두면 이렇게 됩니다.

```
AI가 낸 후보:   [ 10:00 ─ 10:30 ]           ← 30분이라고 적어 놓음
검사 대상:      [ 10:00 ─ 10:30 ]           ← 적힌 만큼만 검사
실제 회의:      [ 10:00 ─────────── 11:00 ] ← 진짜로는 60분

                          [ 10:30 ─ 11:00 ]  ← 이 30분은
                                                아무도 검사 안 함
                                                남의 일정이 있어도 모름
```

**승인하면 남의 회의 위로 밀고 들어가는데 에러도 안 납니다.**

그래서 **검사하기 전에 길이부터 60분으로 다시 씁니다.** 짧으면 늘리고 길면 줄입니다.
늘린 뒤에 업무시간을 넘거나 다른 일정과 겹치면, 그다음 검사가 그 후보를 버립니다.

> **한 줄:** 검사하는 구간과 실제로 등록될 구간이 같아야 검사가 의미가 있습니다.

## 값이 없으면 억지로 안 채웁니다

사용자가 시간대를 직접 고르는 경우엔 소요 시간이 비어 올 수 있습니다.
그때는 **길이를 강제하지 않습니다.** 기준도 없이 60분으로 늘리면 없던 충돌이 생깁니다.

---

# 8. 이게 효과가 있었나 (숫자)

원래는 지시문에 소요 시간 얘기가 **아예 없었습니다.** 결과는 이랬습니다.

```
바꾸기 전:   완료된 제안 105건 중  101건이 30분     ← 사실상 한 값만 나옴
```

안건을 안 보고 습관적으로 30분을 쓰고 있었던 겁니다.

지시문에 4장의 기준을 넣고, **같은 입력 30건**을 다시 돌렸습니다.

| | 전 | 후 |
|---|---|---|
| 소요 시간 | 30분 30건 (**1가지**) | 30분 7 · 60분 19 · 90분 4 (**3가지**) |
| 선호 기간 폭 | 약 30분 | 평균 10일 |

**중요한 건 "흩어졌다"가 아니라 "갈렸다"입니다.**
단순 확인 건은 바꾼 뒤에도 그대로 30분에 남았습니다. 아무렇게나 퍼진 게 아니라 안건에
따라 나뉜 겁니다.

> 참고: 일정 후보가 0개가 되는 실패(89건 중 2건)는 소요 시간 문제가 아니라
> **선호 기간을 30분짜리 한 칸으로 준 것**이 원인이었습니다. 두 값은 같이 정해지지만
> 고장 나는 모습이 다릅니다.

# 9. 솔직한 한계

## 제일 큰 것: 맞았는지 잴 수가 없습니다

```
제안:  60분  →  승인  →  일정에 60분으로 저장  →  실제로는 90분 걸림
                                                    ↑
                                          이걸 아무도 안 적습니다
```

저장된 일정의 길이는 **제안한 값이 그대로 들어간 것**이라, 실제 걸린 시간이 아닙니다.
그래서 지금은 **"예측이 몇 % 맞았다"를 말할 수 없습니다.** 8장도 "정확했다"가 아니라
"안건에 따라 갈렸다"까지만 주장합니다.

**재는 방법을 만드는 게 먼저입니다.**

## 나머지

| 항목 | 상태 |
|---|---|
| 일정 종류 딱지 (첫 전화·데모·제품교육 등 11종) | DB엔 있는데 **AI에게 안 보냅니다.** "지난 데모는 평균 90분" 같은 근거로 쓸 수 있지만, 실측이 없어서 평균 낼 게 없습니다 |
| 이동·준비 시간 | 없습니다. 병원 왕복 두 시간이 일정에 안 잡힙니다 |
| 사람마다 다른 기본값 | 설계 문서에만 있고 미구현입니다 |
| 참석자 수 | 안 보냅니다. 원장님이 들어오는지 여부는 안건 문장으로만 간접 전달됩니다 |

# 10. 나중에 이 기준을 고칠 때

1. **지시문을 고치면 버전 번호를 같이 올린다.** (`propose_next_meeting.v4` → `v5`)
   안 올리면 나중에 실행 기록을 봐도 어느 기준으로 나온 값인지 모릅니다.
2. **두 군데를 같이 본다.** 지시문(태도)과 필드 설명(구간표)에 나눠 적혀 있어서, 한쪽만
   고치면 반대로 유도합니다.
3. **분포로 확인한다.** 같은 입력 30건 이상을 돌려서 값이 어떻게 퍼지는지 봅니다.
   - 한 값에 몰리면 → 기준이 안 읽힌 것
   - 단순 확인 건까지 길어지면 → 너무 세게 밀어붙인 것

# 한 장 요약

| 질문 | 답 |
|---|---|
| 누가 정하나 | **AI가** 정합니다 |
| 뭘 보고 정하나 | **안건**이 주된 근거, 딱지·간격은 참고 |
| 코드에 규칙표가 있나 | **없습니다.** 지시문에 기준만 있습니다 |
| 딱지가 분을 결정하나 | **아닙니다.** 재료로 넘겨줄 뿐입니다 |
| 간격이 분을 결정하나 | **아닙니다.** 일수를 넘겨주고 AI가 판단합니다 |
| 서버는 뭘 하나 | 재료를 모으고, 마지막에 **길이를 강제**합니다 |
| 범위 | 5분 ~ 480분, 값이 없으면 60분 |
| 정확한지 아나 | **모릅니다.** 실측을 안 남기고 있습니다 |
