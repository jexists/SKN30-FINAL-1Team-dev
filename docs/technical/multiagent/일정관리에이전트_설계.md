# 일정관리 에이전트 설계

## 목표(Goal)

계약 에이전트가 회사별로 제안한 미팅 일정과 영업사원의 실제 일정을 함께 검토하여 충돌 없는 최종 일정을 추천한다.

- 여러 회사에서 제안된 미팅 후보 통합
- 사용자의 캘린더 일정 및 근무 가능 시간 확인
- 일정 중복, 이동 시간, 준비 시간, 우선순위 검토
- 충돌 시 계약 에이전트에 대체 일정 요청
- 사용자에게 최종 후보와 추천 이유 제시
- 사용자 승인 후에만 캘린더 일정 생성·수정·삭제
- 승인 대기 중 일정이 바뀌면 재검토

## 모델(LLM)

시간 조건과 업무 맥락을 해석하고 일정 후보의 우선순위를 설명할 수 있는 LLM을 사용한다.

- 자연어 일정 조건 구조화
- 회사별 미팅 목적과 긴급도 비교
- 일정 충돌 및 조정 가능성 해석
- 대체 일정 요청 조건 생성
- 여러 일정 후보 중 최적안 추천
- 사용자가 이해하기 쉬운 추천 이유 작성

실제 시간 계산, 중복 검사, 시간대 변환은 LLM에만 의존하지 않고 캘린더 및 일정 계산 도구를 사용한다.

## 지침(Prompt/Policy)

- 사용자가 접근 가능한 캘린더와 팀 일정만 조회한다.
- 일정의 제목, 참석자, 설명 등은 필요한 범위에서만 사용한다.
- 계약 에이전트의 일정 제안은 확정 일정이 아닌 후보로 취급한다.
- 기존 일정과 겹치는 후보는 그대로 확정하지 않는다.
- 충돌 시 미팅 목적, 마감일, 참석자 조건을 포함해 계약 에이전트에 대체 후보를 요청한다.
- 계약 에이전트와의 교류(duplex)는 일정 충돌 시 대체 후보를 요청하고 응답을 받는 범위로 한정한다. 확정된 일정으로 계약 에이전트의 접촉 이력을 갱신하는 기능은 이 설계에 포함하지 않는다.
- 근무시간, 휴일, 시간대, 이동 시간, 준비 시간을 반영한다.
- 사용자가 지정한 일정이나 고정 일정은 임의로 이동하지 않는다.
- 최종 추천안은 먼저 임시 저장한다.
- 일정 생성·변경·취소는 사용자 승인 후에만 실행한다.
- 승인 이후 캘린더나 일정 후보가 변경되면 다시 검토받는다.
- 참석자에게 초대장이나 알림을 보내는 작업도 별도 승인 범위에 포함한다.
- 사용자의 일정 세부 정보를 계약 에이전트에 불필요하게 전달하지 않는다. 가능한 시간대와 충돌 사유만 최소한으로 전달한다.

## 도구(Tools)

- 사용자 및 팀 캘린더 조회 도구
- 가용 시간 검색 도구
- 일정 충돌 검사 도구
- 시간대 및 휴일 계산 도구
- 이동 시간·준비 시간 계산 도구
- 계약 에이전트의 일정 후보 조회 도구
- 계약 에이전트에 대체 일정 요청 도구
- 일정 추천안 임시 저장 도구
- 캘린더 일정 생성·수정·삭제 도구
- 참석자 가용성 조회 도구
- 권한 확인 도구
- 승인 요청 및 승인 결과 조회 도구
- 캘린더 이벤트 버전 확인 도구
- 비동기 작업 및 상태 조회 도구
- 멱등성 키 기반 중복 실행 방지 도구
- 감사 로그 기록 도구

조회 도구와 변경 도구는 분리한다. 캘린더 변경 도구는 유효한 사용자 승인과 최신 캘린더 버전이 확인된 경우에만 실행한다.

## 메모리(Memory)

일정관리 에이전트는 사용자별 일정 선호를 제한적으로 기억한다.

- 기본 근무시간 및 시간대
- 선호하는 미팅 시간대
- 회의별 기본 소요 시간
- 일정 사이의 기본 여유 시간
- 이동 및 준비 시간 규칙
- 피해야 하는 시간대
- 회사별 미팅 빈도
- 사용자가 승인·거절·수정한 일정 제안
- 이전 대체 일정 요청과 응답
- 반복적으로 확인된 일정 조정 기준

사용자의 캘린더 전체 내용을 장기 메모리로 복제하지 않는다. 일정 선호와 조정에 필요한 최소 정보만 저장한다.

## 지식(Knowledge/RAG)

다음 정보를 활용한다.

- 회사별 미팅 목적과 일정 제안
- 계약 단계별 권장 후속 미팅 시점
- 사용자의 근무시간, 휴일, 시간대 정책
- 팀의 일정 운영 규칙
- 미팅 종류별 권장 소요 시간
- 이동·준비 시간 기준
- 참석자 및 회의실 예약 규칙
- 조직의 캘린더 사용 정책

일정 계산에는 구조화된 최신 캘린더 데이터를 우선 사용한다. RAG는 정책이나 권장 기준을 찾는 데 사용하고 실제 가용 여부는 캘린더 도구로 검증한다.

## 계획·추론(Planning)

1. 계약 에이전트가 전달한 일정 후보와 제약조건을 수신한다.
2. 사용자와 캘린더에 대한 접근 권한을 확인한다.
3. 사용자의 최신 일정, 근무시간, 시간대, 휴일을 조회한다.
4. 회사별 후보 일정을 하나의 시간축에서 비교한다.
5. 기존 일정, 다른 후보, 이동·준비 시간과의 충돌을 검사한다.
6. 계약의 긴급도, 미팅 목적, 마감일을 기준으로 우선순위를 정한다.
7. 충돌이 없는 경우 복수의 추천안을 만든다.
8. 충돌이 있는 경우 가능한 시간 범위만 계약 에이전트에 전달해 대체 일정을 요청한다.
9. 대체 후보를 다시 검증하고 최종 추천안을 구성한다.
10. 추천안과 근거를 임시 저장한다.
11. 사용자에게 생성·변경·취소될 일정을 명확히 보여주고 승인을 요청한다.
12. 승인 후 캘린더와 후보 일정의 버전을 다시 확인한다.
13. 변경이 없다면 일정을 실행하고, 변경되었다면 다시 조율한다.

## 상태(State)

| 상태 | 설명 |
|---|---|
| `RECEIVED` | 일정 후보 접수 |
| `VALIDATING` | 입력과 권한 검증 |
| `FETCHING_CALENDAR` | 최신 캘린더 조회 |
| `CHECKING_CONFLICTS` | 일정 충돌 검사 |
| `REQUESTING_ALTERNATIVES` | 계약 에이전트에 대체 일정 요청 |
| `OPTIMIZING` | 후보 비교 및 우선순위 조정 |
| `DRAFTING` | 최종 추천안 작성 |
| `PENDING_APPROVAL` | 사용자 승인 대기 |
| `STALE` | 승인 대기 중 캘린더 또는 원본 후보 변경 |
| `APPROVED` | 사용자 승인 완료 |
| `EXECUTING` | 캘린더 반영 |
| `COMPLETED` | 일정 반영 완료 |
| `FAILED` | 처리 실패 |
| `CANCELLED` | 사용자 취소 |

각 상태에는 작업 ID, 멱등성 키, 캘린더 스냅샷 버전, 후보 일정 버전, 승인 정보, 실행 결과를 기록한다.

## 실행 루프(Agent Loop)

1. 하나 이상의 계약 에이전트로부터 일정 후보를 받는다.
2. 동일한 요청이 처리 중이거나 완료되었는지 멱등성 키로 확인한다.
3. 사용자 권한과 일정 입력값을 검증한다.
4. 최신 캘린더와 일정 제약조건을 조회한다.
5. 충돌과 가용 시간을 계산한다.
6. 충돌이 있으면 계약 에이전트에 대체 후보를 요청한다.
7. 모든 후보가 조율될 때까지 제한된 횟수로 검증을 반복한다.
8. 작업이 길어지면 비동기 작업 ID를 반환하고 상태 조회를 지원한다.
9. 최종 추천 일정을 초안으로 저장한다.
10. 사용자에게 추천 일정, 대안, 충돌 사유, 실행될 작업을 보여준다.
11. 사용자 승인을 기다린다.
12. 승인 후 최신 캘린더 버전과 원본 후보 버전을 재확인한다.
13. 변경이 없으면 캘린더 작업을 한 번만 실행한다.
14. 변경이 있으면 `STALE`로 전환하고 새로운 추천안을 작성한다.
15. 생성된 이벤트 ID와 실행 결과를 저장한다.

## 평가·안전장치(Guardrails)

- 사용자 및 팀 캘린더 접근 권한 검증
- 다른 사용자의 비공개 일정 내용 노출 방지
- 시간대, 일광절약시간, 휴일 변환 정확성 검증
- 중복 일정, 이동 시간, 준비 시간 누락 여부 검사
- 고정 일정 및 사용자가 보호한 시간대 변경 금지
- 사용자 승인 없는 일정 생성·수정·삭제 차단
- 초대장 발송과 참석자 추가 여부를 승인 화면에 명시
- 승인 후 캘린더 변경 시 기존 실행 차단
- 멱등성 키와 이벤트 ID를 통한 중복 일정 생성 방지
- 계약 에이전트 간 대체 일정 요청의 최대 반복 횟수 설정
- 조율이 불가능하면 임의로 확정하지 않고 충돌 원인과 선택지를 제시
- 추천 이유와 적용된 제약조건을 사용자에게 설명
- 도구 오류 발생 시 부분적으로 생성된 이벤트를 탐지하고 복구
- 조회·추천·승인·실행 과정에 대한 감사 로그 기록
