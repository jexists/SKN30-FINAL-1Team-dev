| 항목 | 내용 |
|---|---|
| 제품 | SalesLuv |
| 과제 | B2B 딜의 `Won` 확률 및 승패 예측 |
| 최종 모델 | `Stacking_LR` |
| 모델 버전 | `deal-stacking-lr-v1` |
| 입력 | 13개 범주형 컬럼, 행마다 4개 `Unknown` 마스킹 |
| 분류 임계값 | `0.50` |
| 작성 기준일 | 2026-08-27 |
| 현재 상태 | 선택·평가·전체 재학습·모델 저장·재로드 검증 완료 |

## 1. 결과 요약

공개 Salvirt B2B Sales Dataset 448건을 사용해 미팅 보고서에서 확보할 수 있는 13개 범주형 정보로 딜의 `Won` 확률을 예측했다. 실제 서비스에서 일부 항목이 측정되지 않는 상황을 반영하기 위해 각 행의 13개 컬럼 중 정확히 4개를 `Unknown`으로 바꾼 서로 다른 마스킹 10세트를 구성했다.

최종 모델 `Stacking_LR`는 LogisticRegression, MultinomialNB, ExtraTrees, CatBoost, TabICL의 예측 확률을 입력받아 LogisticRegression 메타모델이 결합하는 분류 앙상블이다. 5-Fold Group CV를 시드 3개로 반복한 비교에서 가장 낮은 평균 Brier Score를 기록했다. 분류 임계값은 `0.50`을 유지했다.

| 지표 | 반복 Group CV | Test 10세트 평균 |
|---|---:|---:|
| Brier ↓ | **0.194406 ± 0.001928** | **0.179131 ± 0.005902** |
| ROC-AUC ↑ | 0.766326 | 0.817164 |
| Accuracy ↑ | 0.720873 | 0.734074 |
| Precision ↑ | 0.695164 | 0.720534 |
| Recall ↑ | 0.802935 | 0.772059 |
| F1 ↑ | 0.745072 | 0.745083 |
| FP / FN | 56.03 / 31.33 | 20.4 / 15.5 |

Test 수치는 원본 135건에 서로 다른 결측 패턴을 적용한 10세트의 평균이다. 열 개 세트는 같은 딜을 공유하므로 독립 표본 1,350건으로 해석하지 않는다.

평가와 모델 선택을 마친 뒤 동일 구성을 전체 448건의 10개 마스킹 세트, 총 4,480행으로 다시 학습했다. 초기 TabICL 파일에는 MPS 실행 장치가 남아 Linux에서 로드되지 않았다. 운영 배포 전 가중치와 예측은 유지하고 직렬화 장치만 CPU로 고친 `deal-stacking-lr-v1` 산출물로 교체했다.

## 2. 데이터와 전처리

### 2.1 데이터셋 설명

Salvirt B2B Sales Dataset은 실제 B2B 영업기회를 익명화한 공개 데이터다. 한 행은 하나의 영업기회를 나타내며, 상품·담당자·고객 상황·구매 절차·요구사항 등 22개 범주형 입력과 최종 결과 `Status`로 구성된다. 이 구조가 SalesLuv의 목표인 미팅 정보 기반 딜 승패 예측과 직접 맞기 때문에 학습 원천으로 선택했다.

| 항목 | 내용 |
|---|---|
| 공식 출처 | [Salvirt B2B Sales Dataset](https://www.salvirt.com/research/b2bdataset/) |
| 연관 연구 | Bohanec, Kljajić Borštnar, Robnik-Šikonja (2017), [Explaining machine learning models in sales predictions](https://doi.org/10.1016/j.eswa.2016.11.010), Expert Systems with Applications 71, 416-428 |
| 원본 크기 | 448행 × 23컬럼: 입력 22개 + 정답 `Status` |
| 입력 형태 | 모든 입력이 범주형 문자열 |
| 정답 분포 | `Lost` 221건(49.33%), `Won` 227건(50.67%) |
| 원본 SHA-256 | `8dee635b95bdcb00896b654efe62fc20177090081c81ef5224e8641ba31c3061` |

클래스 비율은 거의 균형이므로 단순히 다수 클래스를 맞혀 정확도를 높이는 데이터는 아니다. 공식 페이지에는 데이터 라이선스가 명시되어 있지 않아 상용 학습·재배포 전에 원저작자 허가 여부를 별도로 확인해야 한다.

중복은 삭제하지 않았다. 23개 전체 컬럼 기준 완전중복 후속 행은 83건이고, 최종 13개 입력과 `Status` 기준 중복 후속 행은 226건이다. 반복 행도 서로 다른 실제 영업 사례로 간주해 448건을 모두 보존했다. 다만 같은 13개 입력이 Train과 Test에 동시에 들어가 성능이 부풀지 않도록 198개 입력 조합을 그룹으로 묶어 분할했다. 같은 입력인데 `Won`과 `Lost`가 함께 존재하는 조합 24개도 유지해 현재 입력만으로 구분되지 않는 현실적 불확실성을 반영했다.

### 2.3 결측치 조사와 처리 결정

범주형 데이터이므로 숫자 평균이나 중앙값으로 채우지 않았다. 먼저 `NaN`, 빈 문자열, 문자열 `Unknown`을 구분해 조사하고 셋의 합집합을 실질 결측치로 정의했다. 실제 원본에는 `NaN`과 빈 문자열이 없었고, 결측은 모두 데이터 제공자가 값 미확인을 명시한 `Unknown`이었다.

| 컬럼 | 자연 `Unknown` | 결측률 | `Unknown` 행 Won 비율 | 관측 행 Won 비율 |
|---|---:|---:|---:|---:|
| `Budgt_alloc` | 36 | 8.036% | 13.889% | 53.883% |
| `Purch_dept` | 32 | 7.143% | 15.625% | 53.365% |
| `Competitors` | 20 | 4.464% | 25.000% | 51.869% |
| `Source` | 10 | 2.232% | 20.000% | 51.370% |
| 나머지 9개 입력 | 0 | 0% | - | - |

13개 입력의 총 5,824셀 중 자연 `Unknown`은 98셀(1.683%)이며, 448행 중 72행(16.07%)이 하나 이상을 포함했다. 행당 평균은 0.219개, 중앙값은 0개, 최대는 3개였다.

자연 `Unknown`이 있는 72행의 Won 비율은 19.44%이고 `Unknown`이 없는 376행은 56.65%였다. 이는 인과관계가 아니라 현재 표본에서 확인된 연관성이지만, 행을 삭제하면 Lost 사례를 주로 제거하고 최빈값으로 채우면 값 미확인 자체의 신호를 지울 수 있다. 따라서 행 삭제와 최빈값 대체를 하지 않고 `Unknown`을 `No`와 구분되는 정상 범주로 보존했다. 원본에 `Unknown`이 없던 9개 입력도 실서비스에서 추출되지 않을 수 있으므로 같은 범주를 허용했다.

### 2.4 실서비스의 값 누락 상황을 만드는 방법

실제 미팅 보고서에는 13개 항목이 항상 전부 들어오지 않는다. 예를 들어 예산 확보 여부는 확인했지만 경쟁사나 구매부서 참여 여부는 알 수 없을 수 있다. 이런 상황에서도 모델이 작동하는지 확인하기 위해, 학습 데이터에서도 한 거래의 13개 값 중 약 30%가 확인되지 않은 상황을 만들었다.

13개의 30%는 3.9개이므로 한 행에 최종적으로 `Unknown`이 4개가 되게 했다. 원본에 이미 `Unknown`이 있다면 그대로 인정하고 부족한 개수만 추가했다. 예를 들어 원래 `Unknown`이 2개인 행에는 2개만 더 넣고, 하나도 없는 행에는 4개를 넣었다.

같은 거래에서도 어떤 항목이 빠지느냐에 따라 예측이 달라질 수 있다. 그래서 거래 한 건마다 `Unknown`이 들어가는 위치가 서로 다른 10가지 버전을 만들었다. 이때 같은 조합을 반복해서 사용하지 않았고, 실제 결과인 `Status`도 빠질 위치를 정하는 데 사용하지 않았다.

결과적으로 원본 448건에서 10개 버전씩 총 4,480행이 만들어졌다. 이 4,480행은 새로운 거래 4,480건이 아니라, 같은 448건을 서로 다른 값 누락 상황으로 보여준 학습용 변형이다. 목적은 특정 한 번의 무작위 결측에 결과가 좌우되지 않게 하고, 일부 정보가 없어도 모델이 비슷한 판단을 내리는지 확인하는 것이다.

### 2.5 학습용과 평가용을 나누는 방법

원본에는 13개 입력값이 완전히 같은 거래가 반복해서 등장한다. 이런 거래 하나가 Train에 있고 똑같은 거래가 Test에도 있으면, 모델이 규칙을 배운 것이 아니라 이미 본 값을 기억해서 높은 점수를 낼 수 있다.

이를 막기 위해 13개 입력값이 같은 행을 하나의 묶음으로 만들었다. 총 448건은 198개 묶음으로 정리되며, 같은 묶음은 Train 또는 Test 중 한쪽에만 들어가게 했다. `Status`는 묶음을 만드는 데 사용하지 않았기 때문에 같은 입력에서 `Won`과 `Lost`가 모두 나온 경우도 하나의 묶음으로 함께 이동한다.

약 70%를 학습용, 30%를 평가용으로 나눴다. 정답 비율도 두 데이터가 비슷하도록 맞췄다. 앞에서 만든 10개 값 누락 버전에도 모두 같은 분할 기준을 적용했다.

| 구분 | 원본 행 | 입력 그룹 | Lost / Won | 마스킹 후 구조 |
|---|---:|---:|---:|---:|
| Train | 313 | 138 | 154 / 159 | 3,130행 × 13컬럼 |
| Test | 135 | 60 | 67 / 68 | 135행 × 13컬럼, 10세트 |

따라서 한 거래와 그 거래에서 만든 10개 값 누락 버전은 모두 Train 또는 Test 한쪽에만 존재한다. 중복된 영업 사례는 학습에 사용하면서, 모델이 Test의 정답을 미리 본 것처럼 평가되는 문제는 막았다.

### 2.6 모델이 읽을 수 있는 형태로 바꾸는 방법

13개 입력은 숫자가 아니라 `Yes`, `No`, `High`, `Project` 같은 글자 범주다. LogisticRegression, MultinomialNB, ExtraTrees는 이 글자를 바로 학습할 수 없으므로, 각 범주에 해당하는지를 0과 1로 표시하는 One-Hot Encoding을 모델 내부에서 적용했다. 이 과정을 거치면 13개 입력이 39개 숫자 컬럼으로 바뀐다.

CatBoost와 TabICL은 범주형 값을 직접 다룰 수 있으므로 13개 글자 범주를 그대로 사용했다. 두 모델에는 One-Hot Encoding을 다시 적용하지 않았다.

`Unknown`은 값이 확인되지 않았다는 뜻으로 미리 등록한 정상 범주다. 따라서 `Unknown`이 들어와도 오류가 나지 않는다. 반면 허용 목록에 없는 새로운 문자열이나 오탈자가 들어오면 구조화 오류로 판단해 입력 단계에서 막는다.

## 3. 학습과 평가 설계

### 3.1 처음 비교할 5개 모델을 선택한 이유

전처리 결과는 원본 448건, 최종 입력 13개, 모든 입력이 범주형이며 한 행에 `Unknown`이 4개씩 포함된 작은 표형 데이터다. 또한 최종 목표가 `Won` 확률이므로 각 모델에서 확률을 얻을 수 있어야 한다. 한 종류의 모델만 비교하면 특정 학습 방식에 유리한 결론이 날 수 있어, 서로 다른 방식으로 데이터를 해석하는 다섯 계열을 선택했다. 이후 앙상블에서 비슷한 모델만 합치는 일을 피하려는 목적도 있다.

| 모델 | 선정 이유 | 입력 처리 |
|---|---|---|
| LogisticRegression | 작은 데이터에서 과적합을 규제로 제어하기 쉽고, 각 범주의 영향을 선형으로 합산하는 안정적인 확률 기준선이 됨 | 고정 범주 One-Hot Encoding 후 학습 |
| MultinomialNB | 범주와 승패가 함께 나타나는 빈도만으로 만들 수 있는 단순 확률 기준을 확인함. 복잡한 상호작용을 학습하는 모델과 다른 판단 방식을 제공함 | 고정 범주 One-Hot Encoding 후 학습 |
| ExtraTrees | 여러 무작위 트리를 사용해 범주 조합의 비선형 관계를 학습함. 선형 모델이 놓칠 수 있는 조건 조합을 확인함 | 고정 범주 One-Hot Encoding 후 학습 |
| CatBoost | 범주형 데이터를 직접 다루도록 설계됐으며, 원핫 변환 없이 범주와 범주 조합의 관계를 학습할 수 있음 | 13개 원본 범주형 컬럼 직접 처리 |
| TabICL | 사전학습된 표형 파운데이션 모델이 448건 규모의 작은 데이터에서 기존 ML보다 나은지 확인하기 위한 최신 계열 비교군임 | 13개 원본 범주형 컬럼 직접 처리, 실행 시 MPS 사용 |

LogisticRegression은 선형 모델, MultinomialNB는 빈도 기반 확률 모델, ExtraTrees는 배깅 트리, CatBoost는 범주형 부스팅, TabICL은 표형 파운데이션 모델을 대표한다. 입력을 사용하지 않고 Train의 평균 승률만 반환하는 Dummy 모델도 기준선으로 실행했지만, 실제 후보 5개에는 포함하지 않았다.

One-Hot Encoding 결과는 39개 컬럼이다. 등록되지 않은 범주는 오류로 처리하며, 측정되지 않은 값은 명시적인 `Unknown` 범주를 사용한다.

### 3.2 Brier Score를 선택 기준으로 사용한 이유

SalesLuv가 제공해야 하는 핵심 결과는 단순한 `Won` 또는 `Lost` 분류만이 아니라 `Won`일 확률이다. 이 확률은 거래 우선순위와 영업 파이프라인을 판단하는 데 사용되므로, 맞고 틀린 개수뿐 아니라 **표시된 확률을 실제로 얼마나 믿을 수 있는지**가 중요하다.

Brier Score는 `평균((Won 예측확률 - 실제 정답)^2)`로 계산하며 낮을수록 좋다. 실제 정답은 `Won=1`, `Lost=0`을 사용한다. 예를 들어 실제로 Lost인 거래에 Won 확률을 0.9로 주면 오차는 0.81이고, 0.6으로 주면 0.36이다. 따라서 틀린 예측을 지나치게 확신할수록 더 큰 불이익을 준다. 모든 행의 확률을 평가하고, 실제 결과에 맞는 정직한 확률을 내도록 평가한다는 점에서 이번 서비스 목적과 맞는다.

| 지표 | 확인하는 내용 | 이번 활용 방식 |
|---|---|---|
| Brier Score | 예측 확률과 실제 결과의 차이 | 모델·하이퍼파라미터의 주 선택 기준 |
| ROC-AUC | Won 거래가 Lost 거래보다 높은 점수를 받는지 | 거래 순위 구분 능력 확인 |
| Accuracy·F1 | 임계값 적용 후 최종 분류가 얼마나 맞는지 | 분류 성능 보조 확인 |
| Precision·Recall | Won 예측의 신뢰도와 실제 Won 탐지 비율 | 한쪽 오류로 치우치는지 확인 |
| FP·FN | 어떤 종류의 업무상 오류가 발생했는지 | 영업 위험과 임계값 판단에 사용 |

Accuracy와 F1은 확률을 `Won` 또는 `Lost`로 바꾸는 임계값에 따라 달라지고, ROC-AUC는 거래의 순서는 평가하지만 0.8이라는 확률 자체가 믿을 만한지는 평가하지 않는다. 그래서 튜닝과 모델 선택은 CV Brier Score를 중심으로 진행하고, AUC·Accuracy·F1·FP·FN을 함께 확인했다. Brier는 모든 모델이 학습 과정에서 직접 최소화한 공통 손실함수가 아니라, 학습된 후보 중 어떤 모델과 파라미터를 선택할지 정한 평가 기준이다.

## 4. 최종 모델 선정

### 4.1 FP를 중요하게 본 이유

이 보고서에서 양성 클래스는 `Won`이다. 따라서 FP(False Positive)는 모델이 성사 가능성이 있다고 판단했지만 실제로는 `Lost`가 된 거래를 뜻한다.

SalesLuv에서 FP가 발생하면 실제로는 `Lost` 위험이 높아 추가 관리가 필요한 거래가 `Won` 가능성이 높은 거래로 표시된다. 영업팀은 해당 거래가 쉽게 성사될 것이라고 오인해 위험 신호를 놓치고, 추가 확인·설득·조건 조정이 필요한 시점을 지나칠 수 있다. 또한 잘될 것으로 잘못 표시된 거래를 우선순위에 올리면서 실제로 성사 가능성이 높은 다른 거래에 사용할 시간과 인력이 줄어들 수 있다.

이러한 낙관적 오판은 파이프라인과 예상 매출도 실제보다 높게 만든다. 그 결과 인력 배치, 일정, 재고, 경영 판단이 잘못될 수 있으며, 같은 문제가 반복되면 영업 담당자가 모델의 승률 자체를 신뢰하지 않게 된다. 이런 이유로 전체 성능이 비슷한 모델끼리 비교할 때는 FP가 낮은 모델을 더 안전한 모델로 본다.

다만 FP만 0으로 만드는 것은 올바른 목표가 아니다. 모든 거래를 `Lost`로 예측하면 FP는 없어지지만 실제 `Won` 거래를 전부 놓친다. 임계값을 높여도 FP는 줄어드는 대신 FN이 늘고 Recall이 낮아진다. 따라서 이번 학습은 다음 두 문제를 분리했다.

1. 먼저 Brier Score로 확률 자체가 실제 결과와 잘 맞는 모델을 고른다.
2. 이후 FP와 FN의 실제 업무 비용을 바탕으로 분류 임계값을 결정한다.

현재 모델은 후보를 같은 조건으로 비교하고 운영 기준을 단순하게 유지하기 위해 임계값을 `0.50`으로 확정했다. FP와 FN의 실제 비용은 운영 지표로 기록하되, 이번 모델의 임계값은 별도로 조정하지 않았다. 향후 충분한 실제 데이터와 비용 근거가 확보될 때만 새 모델 버전에서 재검토한다.

### 4.2 최종 선택 결과

`Stacking_LR`를 최종 모델로 선정했다.

1. 반복 Group CV에서 가장 낮은 Brier Score `0.194406`을 기록했다.
2. Test AUC `0.817164`, Accuracy `0.734074`, FP `20.4`, FN `15.5`로 확률·분류·오류 유형의 균형을 확인했다.
3. 후보를 동일한 기준으로 비교하고 운영을 단순화하기 위해 기본 임계값 `0.50`을 유지했다.
4. 후보 선택은 반복 CV 순위로 확정했다. Test의 Soft Voting과 ExtraTrees 우수 지표는 참고 결과로 기록했다.

상위 세 후보의 CV Brier 차이는 `0.000324` 이내다. 기본 모델 확률의 상관계수도 약 `0.84~0.97`로 높아 앙상블 개선 폭이 작다. 현재 결과는 `Stacking_LR`의 절대적 우위를 뜻하지 않으며, 운영 복잡도와 재검증 결과를 함께 관리한다.

Test에서 LogisticRegression의 FP는 `16.5`로 가장 낮았지만 FN은 `22.2`로 늘었고 Accuracy와 F1도 Stacking보다 낮았다. 따라서 FP 하나만으로 모델을 정하지 않고, 반복 CV Brier를 우선하면서 AUC·Accuracy·F1과 FP/FN의 균형을 함께 확인했다.
