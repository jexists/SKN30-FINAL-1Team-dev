# 머신러닝/딥러닝 학습결과서

| 항목 | 내용 |
|---|---|
| 제품 | SalesLuv |
| 과제 | B2B 딜의 `Won` 확률 및 승패 예측 |
| 최종 모델 | RF·LR·ExtraTrees·CatBoost를 결합한 `Stacking_LR` |
| 모델 버전 | `deal-paper-rf-ensemble-v1` |
| 학습 입력 | 13개 범주형 컬럼, 행마다 4개 `Unknown` 마스킹 |
| 분류 임계값 | `0.50` |
| 작성 기준일 | 2026-08-31 |

## 1. 결과 요약

공개 Salvirt B2B Sales Dataset 448건을 사용해 업무 보고서에서 확보할 수 있는 13개 범주형 정보로 딜의 `Won` 확률을 예측했다. 실제 서비스에서 일부 항목이 측정되지 않는 상황을 반영하기 위해 각 행의 13개 컬럼 중 정확히 4개를 `Unknown`으로 바꾼 서로 다른 마스킹 10세트를 구성했다.

논문에서 선정한 RandomForest를 베이스라인 모델 계열로 삼았다. 논문의 학습 완료 파일과 세부 하이퍼파라미터·튜닝 탐색 방법은 확인되지 않아, 공개된 Train 80% / Test 20%·30회 반복 평가 방식을 참고해 우리 데이터 조건에서 RF를 직접 학습했다. 이렇게 완성한 RF를 **우리 실험의 베이스라인**으로 고정하고, RF 튜닝과 분류 앙상블로 발전시켰다.

우리 실험은 13개 입력·결측 마스킹을 유지하고 동일 입력 그룹을 분리했다. GridSearch는 논문에서 확인한 세부 튜닝법을 복제한 것이 아니라 우리가 추가한 개선 절차다. 파라미터는 각 회차의 Train 내부에서만 선택했고 분류 임계값은 모든 후보에서 `0.50`을 유지했다.

| 단계 | Accuracy ↑ | ROC-AUC ↑ | Brier ↓ | FP ↓ | FN ↓ |
|---|---:|---:|---:|---:|---:|
| RF 기준선 | 0.695847 | 0.740949 | 0.209706 | 15.59 | 12.54 |
| RF 튜닝 | 0.733833 | 0.775560 | 0.190198 | 16.77 | 7.64 |
| 최종 모델 `Stacking_LR` | 0.735980 | 0.778318 | 0.187965 | 16.15 | 8.09 |

수치는 회차별 Test 마스킹 10세트를 먼저 평균하고, 이를 다시 30회 평균한 결과다. 같은 원본 거래가 반복해서 사용되므로 독립된 300개 실험이나 새로운 4,480건의 데이터로 해석하지 않는다.

논문 자체의 RF 성적은 Accuracy **78.2%**, AUC **0.85**였다. 위 표의 RF 기준선 **69.58% / 0.740949**는 우리가 13개 컬럼·결측 상황·그룹 분리 조건으로 직접 얻은 값이다. 같은 조건에서 발전시킨 최종 Stacking은 Accuracy **73.60%**, AUC **0.778318**로 기준선보다 각각 **4.01%p**, **0.037369** 개선됐으며 Brier는 **0.021741** 낮아졌다. 논문은 22개 입력을 사용했으므로 개선 효과는 논문 점수가 아닌 자체 RF 기준선과 비교했다.

Stacking은 튜닝 RF보다 Accuracy·AUC·Brier가 소폭 개선되고 FP도 줄었다. 다만 FN은 늘었고, 튜닝 전 RF 기준선보다 FP가 적어진 것은 아니다. 최종 산출물은 사전에 정한 **1회차 Train 357건의 마스킹 3,570행으로 학습한 모델**이다. 학습 절차의 30회 평균과 저장 모델의 개별 평가 결과를 구분해 제시했다.

## 2. 데이터와 전처리

### 2.1 데이터셋 설명

Salvirt B2B Sales Dataset은 실제 B2B 영업기회를 익명화한 공개 데이터다. 한 행은 하나의 영업기회를 나타내며, 상품·담당자·고객 상황·구매 절차·요구사항 등 22개 범주형 입력과 최종 결과 `Status`로 구성된다. 이 구조가 SalesLuv의 목표인 미팅 정보 기반 딜 승패 예측과 직접 맞기 때문에 학습 원천으로 선택했다.

| 항목 | 내용 |
|---|---|
| 공식 데이터 출처 | [Salvirt B2B Sales Dataset](https://www.salvirt.com/research/b2bdataset) |
| 연관 연구 | Bohanec, Kljajić Borštnar, Robnik-Šikonja (2017), [Explaining machine learning models in sales predictions](https://doi.org/10.1016/j.eswa.2016.11.010), Expert Systems with Applications 71, 416-428 |
| 원본 크기 | 448행 × 23컬럼: 입력 22개 + 정답 `Status` |
| 입력 형태 | 모든 입력이 범주형 문자열 |
| 정답 분포 | `Lost` 221건(49.33%), `Won` 227건(50.67%) |

실제 학습에는 [Hugging Face 고정 리비전 배포본](https://huggingface.co/datasets/markobo/B2B_Sales_data/resolve/c3bae20f010d8ec74f6e9f85ef19368811dd15d3/Salvirt_B2B_ML_dataset_HF.csv)의 CSV를 사용했다. 배포 리비전·원본 해시·라이선스 표기 근거는 [데이터 수집 보고서](../데이터%20수집%20보고서.md#33-외부-학습-데이터)에 제시했다.

클래스 비율은 거의 균형이므로 단순히 다수 클래스를 맞혀 정확도를 높이는 데이터는 아니다.

중복은 삭제하지 않았다. 23개 전체 컬럼 기준 완전중복 후속 행은 83건이고, 최종 13개 입력과 `Status` 기준 중복 후속 행은 226건이다. 입력과 정답이 같다는 이유만으로 사례를 삭제하지 않고 448건을 모두 보존했다. 다만 같은 13개 입력이 Train과 Test에 동시에 들어가 성능이 부풀지 않도록 198개 입력 조합을 그룹으로 묶어 분할했다. 같은 입력인데 `Won`과 `Lost`가 함께 존재하는 조합 24개도 유지해 현재 입력만으로 구분되지 않는 현실적 불확실성을 반영했다.

### 2.3 결측치 조사와 처리 결정

범주형 데이터이므로 숫자 평균이나 중앙값으로 채우지 않았다. 먼저 `NaN`, 빈 문자열, 문자열 `Unknown`을 구분해 조사하고 셋의 합집합을 실질 결측치로 정의했다. 실제 원본에는 `NaN`과 빈 문자열이 없었고, 결측은 모두 데이터 제공자가 값 미확인을 명시한 `Unknown`이었다.

| 컬럼 | 자연 `Unknown` | 결측률 | `Unknown` 행 Won 비율 | 관측 행 Won 비율 |
|---|---:|---:|---:|---:|
| `Budgt_alloc` | 36 | 8.036% | 13.889% | 53.883% |
| `Purch_dept` | 32 | 7.143% | 15.625% | 53.365% |
| `Competitors` | 20 | 4.464% | 25.000% | 51.869% |
| `Source` | 10 | 2.232% | 20.000% | 51.370% |
| 나머지 9개 입력 | 0 | 0% | - | - |

13개 입력의 총 5,824셀 중 자연 `Unknown`은 98셀(1.683%)이며, 448행 중 72행(16.07%)이 하나 이상을 포함했다. 행당 평균은 0.219개, 중앙값은 0개, 최대는 3개였다.

자연 `Unknown`이 있는 72행의 Won 비율은 19.44%이고 `Unknown`이 없는 376행은 56.65%였다. 이는 인과관계가 아니라 현재 표본에서 확인된 연관성이지만, 행을 삭제하면 Lost 사례를 주로 제거하고 최빈값으로 채우면 값 미확인 자체의 신호를 지울 수 있다. 따라서 행 삭제와 최빈값 대체를 하지 않고 `Unknown`을 `No`와 구분되는 정상 범주로 보존했다. 원본에 `Unknown`이 없던 9개 입력도 실서비스에서 추출되지 않을 수 있으므로 같은 범주를 허용했다.

### 2.4 실서비스의 값 누락 상황을 만드는 방법

실제 서비스에서는 미팅 보고서에 해당 정보가 언급되지 않거나 구조화 Agent가 값을 확정하지 못해, 거래 한 건의 13개 입력 항목 중 **약 30%가 누락될 것으로 예상했다.** 예를 들어 예산 확보 여부는 확인했지만 경쟁사나 구매부서 참여 여부는 알 수 없을 수 있다. 30%는 서비스 설계 단계에서 설정한 예상 결측률이며, 실제 사용자 데이터에서 측정한 비율은 아니다.

이 예상 입력 조건을 학습·평가에 반영하기 위해 **13개 × 30% = 3.9개를 반올림해, 행마다 최종 `Unknown` 개수를 4개로 정했다.** 원본에 이미 `Unknown`이 있다면 그대로 인정하고 부족한 개수만 추가했다. 예를 들어 원래 `Unknown`이 2개인 행에는 2개만 더 넣고, 하나도 없는 행에는 4개를 넣었다.

같은 거래에서도 어떤 항목이 빠지느냐에 따라 예측이 달라질 수 있다. 그래서 거래 한 건마다 `Unknown`이 들어가는 위치가 서로 다른 10가지 버전을 만들었다. 이때 같은 조합을 반복해서 사용하지 않았고, 실제 결과인 `Status`도 빠질 위치를 정하는 데 사용하지 않았다.

결과적으로 원본 448건에서 10개 버전씩 총 4,480행이 만들어졌다. 이 4,480행은 새로운 거래 4,480건이 아니라, 같은 448건을 서로 다른 값 누락 상황으로 보여준 학습용 변형이다. 목적은 특정 한 번의 무작위 결측에 결과가 좌우되지 않게 하고, 일부 정보가 없어도 모델이 비슷한 판단을 내리는지 확인하는 것이다.

향후 실제 사용자 미팅 데이터와 거래의 승패 결과가 쌓이면, 항목별 결측률과 어떤 항목이 함께 누락되는지를 분석할 예정이다. 이를 바탕으로 현재의 30% 가정을 실제 입력 분포에 맞게 조정하고, 마스킹 방식·전처리·모델 하이퍼파라미터를 튜닝할 계획이다.

### 2.5 학습용과 평가용을 나누는 방법

원본에는 13개 입력값이 완전히 같은 거래가 반복해서 등장한다. 이런 거래 하나가 Train에 있고 똑같은 거래가 Test에도 있으면, 모델이 규칙을 배운 것이 아니라 이미 본 값을 기억해서 높은 점수를 낼 수 있다.

이를 막기 위해 13개 입력값이 같은 행을 하나의 묶음으로 만들었다. 총 448건은 198개 묶음으로 정리되며, 같은 묶음은 Train 또는 Test 중 한쪽에만 들어가게 했다. `Status`는 묶음을 만드는 데 사용하지 않았기 때문에 같은 입력에서 `Won`과 `Lost`가 모두 나온 경우도 하나의 묶음으로 함께 이동한다.

`GroupShuffleSplit`으로 198개 묶음 중 158개를 Train, 40개를 Test에 배정하는 무작위 분할을 30회 만들었다. 그룹 수 기준 약 80:20이며, 묶음마다 거래 수가 달라 원본 행 비율은 정확한 80:20이 아니다. 실제 Test 행 비율은 13.17~29.02%, 평균 20.50%였다. 바깥 분할은 정답 비율을 강제로 맞추지 않고, 각 회차에 두 클래스가 모두 있는지 확인했다.

| 구분 | 1회차 원본 행 | 입력 그룹 | 마스킹 후 구조 |
|---|---:|---:|---|
| Train | 357 | 158 | 3,570행 × 13컬럼 |
| Test | 91 | 40 | 91행 × 13컬럼, 10세트 |

한 거래와 그 거래의 10개 값 누락 버전은 각 회차 안에서 모두 Train 또는 Test 한쪽에만 존재한다. 그룹은 마스킹 전 입력으로 정했으며 `Status`는 사용하지 않았다. 세 단계 모두 같은 30개 분할과 마스킹을 재사용해, 다른 데이터로 학습해서 생긴 차이를 모델 개선으로 오인하지 않도록 했다.

한편 서로 다른 원본 입력도 일부 값을 가리면 같은 입력으로 보일 수 있다. 이는 결측으로 정보가 줄어드는 결과이며, 마스킹 이후의 모든 입력 조합이 양쪽에서 반드시 다르다는 뜻은 아니다.

### 2.6 모델이 읽을 수 있는 형태로 바꾸는 방법

13개 입력은 숫자가 아니라 `Yes`, `No`, `High`, `Project` 같은 글자 범주다. RandomForest, LogisticRegression, ExtraTrees에는 각 범주에 해당하는지를 0과 1로 표시하는 One-Hot Encoding을 모델 내부에서 적용했다. 허용 범주를 고정하고 범주별 첫 항목을 제외하는 `drop="first"` 설정을 사용해 39개 숫자 컬럼으로 변환했다.

CatBoost에는 13개 원본 글자 범주를 그대로 전달하고 범주형 컬럼을 지정했다. 원핫 인코딩을 다시 적용하지 않았다.

`Unknown`은 값이 확인되지 않았다는 뜻으로 미리 등록한 정상 범주다. 따라서 `Unknown`이 들어와도 오류가 나지 않는다. 반면 허용 목록에 없는 새로운 문자열이나 오탈자가 들어오면 구조화 오류로 판단해 입력 단계에서 막는다.

실제 추론에서 임의의 값을 지워 `Unknown`을 4개로 맞추지는 않는다. 구조화 Agent가 확인하지 못한 값만 `Unknown`으로 전달한다.

## 3. 학습과 평가 설계

### 3.1 RF 기준선과 추가 모델의 선정 이유

논문에서 가장 좋은 Accuracy·AUC를 기록한 RandomForest를 기준 모델로 정했다. 이후 RF를 튜닝하고, 다른 판단 방식을 더할 수 있는 세 모델을 함께 비교했다.

| 모델 | 선정 이유 | 입력 처리 |
|---|---|---|
| RandomForest | 논문에서 선정한 모델 계열이며, 여러 나무의 예측을 평균해 비선형 관계를 학습함. 동일 조건에서 튜닝 효과를 확인할 출발점 | 고정 범주 One-Hot Encoding 후 학습 |
| LogisticRegression | 작은 데이터에서 규제로 복잡도를 제어하고 범주의 영향을 선형으로 합산함. 트리와 다른 판단을 추가 | 고정 범주 One-Hot Encoding 후 학습 |
| ExtraTrees | 여러 무작위 트리를 사용해 범주 조합의 비선형 관계를 학습함. 선형 모델이 놓칠 수 있는 조건 조합을 확인함 | 고정 범주 One-Hot Encoding 후 학습 |
| CatBoost | 범주형 데이터를 직접 다루도록 설계됐으며, 원핫 변환 없이 범주와 범주 조합의 관계를 학습할 수 있음 | 13개 원본 범주형 컬럼 직접 처리 |

논문은 무작위 Train 80% / Test 20% 분할을 30회 반복했고, RF 평균 Accuracy `0.782`, AUC `0.85`를 보고했다. 공개 본문만으로 정확한 RF 파라미터·튜닝 탐색 방법과 학습된 모델 파일은 확인하지 못했다. 따라서 논문에서 확인한 모델 계열과 반복 평가 방식을 참고하되, 기본 설정으로 직접 학습한 RF를 우리 기준선으로 삼았다. 논문 모델의 완전한 복원은 아니다. 입력도 논문의 22개와 달리 13개이고 추가 결측과 그룹 분리가 있으므로 논문 점수와 직접 우열을 판단하지 않는다.

### 3.2 Brier Score를 선택 기준으로 사용한 이유

과제는 `Won`과 `Lost`를 구분하는 이진분류다. 모델은 먼저 `Won` 확률을 계산하고 임계값 `0.50` 이상이면 `Won`으로 분류한다. 확률 0.51과 0.99는 같은 `Won`이지만 확신의 정도는 다르다. SalesLuv는 이 점수를 거래 우선순위와 위험 판단에도 사용하므로, **분류가 맞는지뿐 아니라 잘못된 판단을 지나치게 확신하지 않는지**도 확인해야 한다.

Brier Score는 `평균((Won 예측확률 - 실제 정답)^2)`로 계산하며 낮을수록 좋다. 실제 정답은 `Won=1`, `Lost=0`을 사용한다. 예를 들어 실제로 Lost인 거래에 Won 확률을 0.9로 주면 오차는 0.81이고, 0.6으로 주면 0.36이다. 따라서 틀린 예측을 지나치게 확신할수록 더 큰 불이익을 준다. 모든 행의 확률을 평가하고, 실제 결과에 맞는 정직한 확률을 내도록 평가한다는 점에서 이번 서비스 목적과 맞는다.

| 지표 | 확인하는 내용 | 이번 활용 방식 |
|---|---|---|
| Brier Score | 예측 확률과 실제 결과의 차이 | 하이퍼파라미터 선택 기준, 후보 선택의 주요 지표 |
| ROC-AUC | Won 거래가 Lost 거래보다 높은 점수를 받는지 | 거래 순위 구분 능력 확인 |
| Accuracy·F1 | 임계값 적용 후 최종 분류가 얼마나 맞는지 | 분류 성능 보조 확인 |
| Precision·Recall | Won 예측의 신뢰도와 실제 Won 탐지 비율 | 한쪽 오류로 치우치는지 확인 |
| FP·FN·FPR | 어떤 업무상 오류가 발생했는지, 실제 Lost 중 FP 비율 | 영업 위험과 후보 간 상충 관계 확인 |

Accuracy와 F1은 분류 임계값에 따라 달라지고, ROC-AUC는 거래의 순서는 평가하지만 0.8이라는 확률의 정확성은 평가하지 않는다. 그래서 하이퍼파라미터는 Train 내부 CV Brier로 선택하고, 후보 간 비교에서는 AUC·Accuracy·FP·FPR 등을 함께 봤다. Brier가 낮다는 사실만으로 실서비스에서 확률이 완전히 보정되었다고 보장할 수는 없다.

Brier는 모든 모델이 직접 최소화한 공통 학습 손실함수가 아니다. RF·ExtraTrees의 분기 기준은 Gini, CatBoost의 학습 손실은 Logloss다. Brier는 학습된 설정 중 무엇을 고를지 정하는 평가 기준으로 사용했다.

### 3.3 RF 기준선과 하이퍼파라미터 튜닝

기준 RF는 나무 100개, 깊이 제한 없음, 최소 잎 샘플 수 1, 분기 피처 수 `sqrt`, Bootstrap 사용, 난수 시드 1로 고정했다. 기준 성능을 먼저 저장한 뒤 다음 64개 조합을 탐색했다.

| 파라미터 | 탐색값 |
|---|---|
| `n_estimators` | 100, 300 |
| `max_depth` | None, 4, 8, 12 |
| `min_samples_leaf` | 1, 5, 10, 20 |
| `max_features` | sqrt, 0.5 |

각 바깥 Train 안에서 `StratifiedGroupKFold(5, shuffle=True, random_state=1)`와 `GridSearchCV(scoring="neg_brier_score")`를 실행했다. 64개 조합 × 5-Fold × 30회로 검증 학습 9,600회를 수행했으며, 최적 설정 재학습과 기준 RF 재현 학습은 별도다. 기본 설정도 탐색에 포함했다. 최소 잎 샘플 수는 원본 거래 수가 아니라 마스킹을 포함한 학습 행 수 기준이다.

각 회차는 자기 Train에서 고른 최적 설정으로 해당 Test를 평가했다. 따라서 30회 평균은 단일 `best_params` 모델이 아니라 **튜닝 절차 전체의 평가**다. 바깥 Test는 파라미터 선택에 사용하지 않았고, 같은 원본·입력 그룹의 변형은 내부 Fold에서도 한쪽에만 배치했다.

RF 튜닝으로 Accuracy는 69.58%에서 73.38%, AUC는 0.740949에서 0.775560으로 높아졌다. Brier는 0.209706에서 0.190198로 낮아졌지만, FP는 15.59건에서 16.77건으로 늘었다. 기본 RF의 마스킹별 300개 평가 기록도 재현해 동일 조건 비교임을 확인했다.

### 3.4 추가 모델 튜닝과 분류 앙상블

RF는 직전 단계에서 **각 회차별로 고른 파라미터**를 재사용했다. LR·ExtraTrees·CatBoost도 같은 회차 Train의 그룹 5-Fold에서 각각 Brier로 튜닝했다.

| 모델 | 탐색 범위 | 조합 수 |
|---|---|---:|
| LogisticRegression | C: 0.01, 0.03, 0.1, 1 / class_weight: None, balanced | 8 |
| ExtraTrees | 깊이: 4, 8, 12 / 최소 잎: 3, 6, 12 / max_features: sqrt, 0.5 / 나무 300개 고정 | 18 |
| CatBoost | 깊이: 3, 4, 6 / 학습률: 0.01, 0.05, 0.1 / L2 규제: 3, 7 / 반복 200회 고정 | 18 |

추가 탐색은 44개 조합 × 5-Fold × 30회로 검증 학습 6,600회다. 단일 모델 4종과 다음 앙상블 3종을 비교했다.

- Voting 3종: RF·LR·CatBoost의 `Won` 확률을 같은 비중으로 평균한다.
- Voting 4종: RF·LR·ExtraTrees·CatBoost 확률을 같은 비중으로 평균한다.
- `Stacking_LR`: 그룹 3-Fold로 만든 네 모델의 OOF 확률을 LR 메타모델이 결합한다. OOF는 해당 행을 학습에서 제외한 모델의 예측이며, 메타모델은 `C=0.1`로 고정했다.

OOF 생성 시에는 해당 회차 Train에서 고른 기본 모델 파라미터를 고정했다. 파라미터 선택까지 OOF Fold 안에서 다시 실행한 것은 아니므로 OOF 점수를 편향 없는 검증 성적으로 보고하지 않았다. 후보의 성능은 모두 분리된 바깥 Test에서 계산했다.

| 후보 | Accuracy ↑ | AUC ↑ | Brier ↓ | FP ↓ | FN ↓ |
|---|---:|---:|---:|---:|---:|
| RF 튜닝 | 0.733833 | 0.775560 | 0.190198 | 16.77 | 7.64 |
| LogisticRegression | 0.727850 | 0.772088 | 0.190529 | 16.09 | 8.96 |
| ExtraTrees | 0.732910 | 0.776948 | 0.189994 | 16.68 | 7.82 |
| CatBoost | **0.738872** | 0.773243 | 0.190599 | 16.54 | 7.40 |
| Voting 3종 | 0.735595 | 0.778322 | 0.188502 | 16.41 | 7.85 |
| Voting 4종 | 0.736531 | **0.778727** | 0.188461 | 16.42 | 7.76 |
| `Stacking_LR` | 0.735980 | 0.778318 | **0.187965** | 16.15 | 8.09 |

| 후보 | Precision ↑ | Recall ↑ | F1 ↑ | FPR ↓ |
|---|---:|---:|---:|---:|
| RF 튜닝 | 0.706008 | 0.835410 | 0.763253 | 0.384271 |
| LogisticRegression | 0.707623 | 0.811970 | 0.754154 | 0.369847 |
| ExtraTrees | 0.706043 | 0.831085 | 0.761563 | 0.382328 |
| CatBoost | 0.710247 | 0.838148 | 0.766934 | 0.379343 |
| Voting 3종 | 0.709257 | 0.830762 | 0.763363 | 0.376428 |
| Voting 4종 | 0.709887 | 0.832292 | 0.764364 | 0.376246 |
| `Stacking_LR` | 0.711869 | 0.825865 | 0.762654 | 0.370101 |

모두 Test 10세트 평균을 다시 30회 평균한 값이다. FP·FN은 평균 건수라 소수로 표시된다. 회차마다 Test 크기가 달라 실제 Lost 중 FP의 비율인 FPR도 함께 기록했다. Accuracy는 CatBoost, AUC는 Voting 4종, Brier는 Stacking이 가장 좋았다.

## 4. 최종 모델 선정

### 4.1 FP를 중요하게 본 이유

이 보고서에서 양성 클래스는 `Won`이다. 따라서 FP(False Positive)는 모델이 성사 가능성이 있다고 판단했지만 실제로는 `Lost`가 된 거래를 뜻한다.

SalesLuv에서 FP가 발생하면 실제로는 `Lost` 위험이 높아 추가 관리가 필요한 거래가 `Won` 가능성이 높은 거래로 표시된다. 영업팀은 해당 거래가 쉽게 성사될 것이라고 오인해 위험 신호를 놓치고, 추가 확인·설득·조건 조정이 필요한 시점을 지나칠 수 있다. 또한 잘될 것으로 잘못 표시된 거래를 우선순위에 올리면서 실제로 성사 가능성이 높은 다른 거래에 사용할 시간과 인력이 줄어들 수 있다.

이러한 낙관적 오판은 파이프라인과 예상 매출도 실제보다 높게 만든다. 그 결과 인력 배치, 일정, 재고, 경영 판단이 잘못될 수 있으며, 같은 문제가 반복되면 영업 담당자가 모델의 승률 자체를 신뢰하지 않게 된다. 이런 이유로 전체 성능이 비슷한 모델끼리 비교할 때는 FP가 낮은 모델을 더 안전한 모델로 본다.

다만 FP만 0으로 만드는 것은 올바른 목표가 아니다. 모든 거래를 `Lost`로 예측하면 FP는 없어지지만 실제 `Won` 거래를 전부 놓친다. 임계값을 높이면 보통 FP는 줄어드는 대신 FN이 늘고 Recall이 낮아진다. 그래서 하이퍼파라미터 선택과 임계값 조정을 구분했다.

Train 내부 Brier로 파라미터를 고른 뒤, 모든 후보를 임계값 `0.50`의 공통 조건에서 비교했다. 분류는 `Won 확률 >= 0.50`일 때 `Won`으로 처리한다.

### 4.2 최종 선택 결과

모델 수를 늘리는 것 자체를 목표로 삼지 않았다. 단일 모델 4종, 3개·4개 모델의 Soft Voting, 4개 모델의 Stacking을 동일 조건에서 비교한 뒤, **예측 성능과 FP를 함께 고려해 최종 구성을 선정했다.** 최종 구성은 RF·LR·ExtraTrees·CatBoost의 기본 모델 4개와 이들의 예측 확률을 결합하는 LR 메타모델 1개다.

튜닝 RF보다 30회 평균 Brier·Accuracy·AUC·FP·FPR이 모두 나빠지지 않고 하나 이상 개선된 후보를 먼저 확인했다. 해당 후보 중 Brier가 가장 낮은 `Stacking_LR`를 선정했다. 조건을 만족한 후보는 Voting 3종, Voting 4종, Stacking이었다. **Brier 단독 순위만으로 결정하거나 FP만 최소화한 선택은 아니다.**

Stacking은 튜닝 RF 대비 Accuracy가 약 0.21%p, AUC가 0.002758 개선되고 Brier가 0.002233 낮아졌다. FP는 16.77→16.15건, FPR은 38.43%→37.01%로 감소했다. 반면 FN은 7.64→8.09건으로 늘고 Recall은 83.54%→82.59%로 낮아졌다. 튜닝 전 RF의 FP 15.59건과 비교하면 Stacking의 FP는 여전히 더 많다.

30회 중 Stacking의 Brier와 AUC는 각각 23회, FP는 20회 튜닝 RF보다 개선됐다. 그러나 반복들이 같은 데이터를 공유하고 평균 차이도 작기 때문에 통계적 우월성을 입증한 것으로 해석하지 않는다. 단일 LR은 FP가 더 적지만 Accuracy·AUC가 낮고 Brier는 더 커, FP 하나만으로 선택하지 않았다.

따라서 현재 구성은 비교한 후보 중 성능을 근거로 선택한 결과다. 기본 모델을 하나씩 제외한 Stacking 비교는 수행하지 않았으므로, 4개가 반드시 필요한 최소 구성이라는 의미는 아니다.

각 회차 Test는 그 회차의 파라미터 선택과 모델 학습에서 제외했다. **최종 모델 계열은 이 30회 비교 결과를 기준으로 선정**했으며, 보고된 성능은 공개 데이터에서의 탐색적 모델 비교 결과다.

## 5. 최종 모델 산출물

평가 전에 지정한 1회차 Train 학습본을 최종 모델 파일로 저장했다. 점수가 가장 높은 회차를 사후에 고르는 대신 저장 기준을 고정했다. 파일 하나에 원핫 인코더를 포함한 기본 모델, CatBoost, LR 메타모델, 입력 구성, 파라미터와 평가 기록을 담았다.

| 항목 | 저장 내용 |
|---|---|
| 모델 파일 | `deal-paper-rf-ensemble-v1.joblib` |
| 구성 | RF·LR·ExtraTrees·CatBoost + LR 메타모델 |
| 학습 범위 | 1회차 Train 원본 357건, 마스킹 3,570행 |
| 별도 평가 | 1회차 Test 원본 91건의 마스킹 10세트 |
| RF 설정 | 나무 300개, 깊이 12, 최소 잎 5, max_features=sqrt |
| LR 설정 | C=0.1, class_weight=None |
| ExtraTrees 설정 | 나무 300개, 깊이 12, 최소 잎 6, max_features=sqrt |
| CatBoost 설정 | 반복 200회, 깊이 4, 학습률 0.05, L2 규제 3 |
| 결합 학습 | 그룹 3-Fold OOF, LR 메타모델 C=0.1 |

저장 모델의 1회차 평가 결과는 다음과 같다. 두 행 모두 같은 Test 91건의 10개 마스킹 평균이다.

| 1회차 모델 | Accuracy ↑ | AUC ↑ | Brier ↓ | FP ↓ | FN ↓ |
|---|---:|---:|---:|---:|---:|
| RF 튜닝 | 0.720879 | 0.726190 | 0.208468 | 15.4 | 10.0 |
| 저장 Stacking | 0.716484 | 0.732313 | 0.206093 | 15.5 | 10.3 |

이 회차에서는 Stacking의 Accuracy와 FP가 튜닝 RF보다 소폭 나쁘다. **30회 평균 개선이 저장 파일 하나의 우월성을 보장하지는 않는다.**

## 6. 결론

SalesLuv의 미팅 정보 기반 딜 예측을 위해 13개 공통 영업 항목을 선정하고, 행당 약 30%의 값 누락을 반영한 전처리와 그룹 분리 평가를 적용했다. 논문의 RF 모델 계열을 출발점으로 직접 학습한 기준선에서 하이퍼파라미터 튜닝과 앙상블 결합을 거쳐 최종 `Stacking_LR` 모델을 완성했다.

최종 모델 계열의 30회 평균 Accuracy는 **73.60%**, AUC는 **0.778318**, Brier는 **0.187965**다. 자체 RF 기준선보다 분류 정확도·순위 구분·확률 오차가 개선됐으며, 튜닝 RF와 비교해서는 FP도 감소했다. 모델 선정에는 정확도만이 아니라 실제 주의가 필요한 거래를 낙관적으로 표시하는 FP의 업무상 위험을 함께 반영했다.

평가 결과는 448건의 공개 데이터와 정해진 결측 조건 안에서의 비교다. 마스킹과 반복 분할은 같은 원본을 공유하므로 독립 표본의 신뢰구간이나 실제 고객 환경의 성능으로 해석하지 않는다. 이 조건 아래에서 전처리부터 모델 비교·선정까지 일관된 기준을 적용하고, 인코딩과 분류기를 포함하는 단일 모델 파일을 최종 산출물로 구성했다.
