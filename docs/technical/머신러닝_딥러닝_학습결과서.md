## 1. 결과 요약

SalesLuv의 딜 조건 22개를 입력받아 계약 성사 클래스인 `Won`의 확률을 예측하는 모델을 학습했다. 최종 모델은 LogisticRegression과 TabICL이 각각 계산한 `P(Won)`을 1:1로 평균하는 Soft Voting 앙상블이다.

모델 및 하이퍼파라미터는 평가용 Test 결과가 아니라 Train 내부 5-Fold 교차검증의 Brier Score가 가장 낮은 조합으로 선택했다. Brier Score는 예측 확률과 실제 결과의 차이를 측정하며 낮을수록 좋다.

| 구분 | Brier ↓ | AUC ↑ | Accuracy ↑ |
|---|---:|---:|---:|
| Train 5-Fold OOF | 0.160846 | 0.841649 | 0.772549 (77.25%) |
| Test 110건 | 0.165947 | 0.830736 | 0.790909 (79.09%) |

운영 임계값은 0.50으로 확정했다. Test에서 `P(Won) >= 0.50`을 Won으로 분류했을 때 110건 중 87건을 맞혔다.

평가를 마친 뒤 동일한 최종 구성을 중복 제거된 전체 365건으로 다시 학습해 배포용 모델 파일로 저장했다. 위 OOF와 Test 수치는 255/110 평가 절차에서 얻은 값이며, 전체 365건으로 다시 학습한 저장 모델을 별도의 독립 데이터로 재평가한 값은 아니다.

## 2. 문제 정의

### 2.1 예측 대상

- 예측 단위: 22개 범주형 조건으로 표현된 하나의 B2B 영업기회
- 정답: `Lost=0`, `Won=1`
- 모델 출력: `Won` 확률
- 운영 분류: `P(Won) >= 0.50`이면 Won 측, 미만이면 Lost 측

### 2.2 사용 목적

- 영업 담당자가 딜의 상대적인 성사 가능성을 참고하도록 지원
- 우선 확인할 딜을 정하는 보조 정보 제공
- 사람이 검토할 수 있는 확률값과 모델 버전 제공

### 2.3 사용하지 않는 목적

- 모델 결과만으로 딜 상태를 자동 변경하지 않는다.
- 계약 승인·거절 또는 담당자 인사평가를 자동 결정하지 않는다.
- 현재 결과를 SalesLuv 실제 고객 데이터에서 검증된 운영 성능으로 해석하지 않는다.

## 4. 평가 설계

### 4.1 Holdout 분할

```python
train_test_split(
    X,
    y,
    train_size=0.7,
    random_state=1,
    stratify=y,
)
```

| 구분 | 전체 | Lost | Won |
|---|---:|---:|---:|
| Train | 255 | 134 | 121 |
| Test | 110 | 58 | 52 |

현재 실험은 일반 층화 무작위 분할이다. 딜·고객사·영업 담당자 단위의 Group Split이나 시간 순서 분할은 적용하지 않았다.

### 4.2 모델 선택

- 1차는 `cv=5`를 지정해 scikit-learn 분류기의 기본 `StratifiedKFold(n_splits=5, shuffle=False)`를 사용했다.
- 2차는 같은 동작의 `StratifiedKFold` 분할 목록을 명시적으로 한 번 만들고 모든 후보에 동일하게 사용했다.
- `GridSearchCV(scoring="neg_brier_score")`로 후보와 하이퍼파라미터를 선택했다.
- scikit-learn은 큰 값을 최적으로 선택하므로 음수 Brier를 사용했고, 표에는 부호를 되돌린 양수 Brier를 기재했다.
- 모델 자체의 학습 loss를 Brier로 변경한 것이 아니라 모델 선택 지표를 Brier로 정한 것이다.
- Test 지표는 후보표에 표시했지만 코드의 `selected_model_name` 계산에는 사용하지 않았다.

이번 교차검증은 중첩 교차검증이나 외부검증이 아니다. 보고서의 OOF 수치는 `Train 내부 선택 CV/OOF 결과`를 뜻한다.

## 5. 실험 과정

### 5.1 1차 후보

- `DummyClassifier(strategy="prior")`
- OneHotEncoder + LogisticRegression
- OneHotEncoder + MultinomialNB + sigmoid 확률 보정
- OneHotEncoder + ExtraTrees
- 범주형 문자열을 직접 처리하는 CatBoost
- 사전학습 표형 기반 모델 TabICL

1차에서는 CV Brier가 가장 낮은 LogisticRegression(`C=0.1`)을 기준점으로 선택했다.

| 1차 후보 | CV Brier ↓ | Test Brier ↓ | Test AUC ↑ | Test Accuracy ↑ |
|---|---:|---:|---:|---:|
| LogisticRegression | 0.161561 | 0.169427 | 0.818800 | 0.754545 |
| TabICL | 0.163147 | 0.163944 | 0.837367 | 0.772727 |
| MultinomialNB | 0.164812 | 0.177516 | 0.821121 | 0.763636 |
| ExtraTrees | 0.168015 | 0.170509 | 0.826426 | 0.800000 |
| CatBoost | 0.172698 | 0.167629 | 0.829410 | 0.763636 |
| Dummy prior | 0.249385 | 0.249259 | 0.500000 | 0.527273 |

### 5.2 2차 튜닝과 앙상블

1차 최적값 주변의 제한된 범위를 다시 탐색했다. ExtraTrees의 sigmoid 보정, Soft Voting과 LogisticRegression 메타 모델을 사용하는 Stacking도 같은 Train 5-Fold CV Brier로 비교했다. 확률을 버리는 Hard Voting은 이번 목적과 맞지 않아 제외했다.

| 순위 | 2차 후보 | CV Brier ↓ | Fold 표준편차 | Test Brier ↓ | Test AUC ↑ | Test Accuracy ↑ |
|---:|---|---:|---:|---:|---:|---:|
| 1 | SoftVoting LR+TabICL | **0.160846** | 0.017887 | 0.165947 | 0.830736 | 0.790909 |
| 2 | LogisticRegression | 0.161561 | 0.016313 | 0.169427 | 0.818800 | 0.754545 |
| 3 | SoftVoting LR+TabICL+ExtraTrees | 0.162007 | 0.018284 | 0.166150 | 0.831068 | 0.800000 |
| 4 | MultinomialNB | 0.162234 | 0.015349 | 0.177860 | 0.825763 | 0.763636 |
| 5 | TabICL | 0.162569 | 0.019479 | 0.164790 | **0.837367** | 0.790909 |
| 6 | Stacking LR+TabICL+ExtraTrees | 0.163075 | 0.019370 | 0.164892 | 0.830405 | **0.809091** |
| 7 | SoftVoting LR+TabICL+ExtraTrees+CatBoost | 0.163518 | 0.019062 | 0.165289 | 0.832394 | 0.790909 |
| 8 | ExtraTrees | 0.166519 | 0.018858 | 0.169055 | 0.830073 | 0.790909 |
| 9 | ExtraTrees sigmoid, ensemble | 0.166879 | 0.021598 | 0.168397 | 0.829410 | 0.790909 |
| 10 | ExtraTrees sigmoid, single | 0.167157 | 0.023154 | 0.167284 | 0.830073 | 0.790909 |
| 11 | CatBoost | 0.170699 | 0.022391 | **0.164446** | 0.835710 | 0.754545 |

Fold 표준편차는 5개 CV fold 점수의 산포이며 95% 신뢰구간이 아니다.

Test AUC는 TabICL 단일 모델이 가장 높고 Test Accuracy는 Stacking이 가장 높았다. 그러나 이 값을 보고 모델을 다시 선택하면 Test 정보가 선택 과정에 들어가므로, 사전에 정한 Train CV Brier 기준에 따라 `SoftVoting_LR_TabICL`을 최종 선택했다.

Soft Voting의 CV Brier는 LogisticRegression보다 0.000715 낮다. 이 차이는 정해진 선택 규칙상 우위지만, 별도의 통계적 유의성을 증명하는 결과로 해석하지 않는다.

## 6. 최종 선택 모델

### 6.1 구성

```text
P(Won) = 0.5 × P(Won | LogisticRegression)
       + 0.5 × P(Won | TabICL)
```

- LogisticRegression: OneHotEncoder와 `C=0.1` LogisticRegression 파이프라인
- TabICL 2.1.1: TabICLv2 체크포인트 `tabicl-classifier-v2-20260212.ckpt`, `n_estimators=16`, quantile 정규화, Latin feature shuffle, 평균 logits, softmax temperature 0.9
- 두 모델의 `classes_`에서 값 `1`의 위치를 확인해 Won 확률을 선택

### 6.2 OOF와 Test 결과

| 지표 | Train 5-Fold OOF | Test |
|---|---:|---:|
| Brier | 0.160846 | 0.165947 |
| AUC | 0.841649 | 0.830736 |
| Accuracy, threshold 0.50 | 0.772549 | 0.790909 |

OOF Brier는 같은 5개 fold의 CV Brier 평균과 수치상 같다. AUC 0.85는 본 실험의 목표나 합격선으로 사용하지 않았다.

## 7. 운영 임계값

3차 노트북은 선택된 모델과 확률을 바꾸지 않고 Train OOF 확률에서 0.05부터 0.99까지 임계값별 Accuracy, Precision, Recall, FPR, FP, FN을 확인했다. 임계값별 지표를 참고하되 별도의 비용함수나 자동 최적화 없이 운영 정책값을 0.50으로 확정했다. 그 뒤 3차 단계에서 해당 임계값을 Test 확률에 적용해 분류 결과를 확인했다.

| 구분 | Accuracy | Precision (Won) | Recall (Won) | FPR | FP | FN |
|---|---:|---:|---:|---:|---:|---:|
| Train OOF | 0.772549 | 0.748031 | 0.785124 | 0.238806 | 32 | 26 |
| Test | 0.790909 | 0.745763 | 0.846154 | 0.258621 | 15 | 8 |

Test 혼동행렬은 실제 행이 Lost/Won, 예측 열이 Lost/Won 순서다.

| 실제/예측 | Lost | Won |
|---|---:|---:|
| Lost | 43 | 15 |
| Won | 8 | 44 |

이번 3차에서는 FP와 FN의 건수·비율을 비교했지만 금액이나 업무 시간으로 환산한 비용함수를 정의하지 않았다. 따라서 0.50을 `비용 최적 임계값`으로 표현하지 않고 `확정된 운영 기준`으로 표현한다.

## 8. 논문 결과와의 관계

[Bohanec et al.](https://doi.org/10.1016/j.eswa.2016.11.010)의 최고 Random Forest 결과는 Accuracy 0.782, AUC 0.85로 보고됐다. 이번 Test 결과는 Accuracy 0.790909, AUC 0.830736이다.

| 비교 조건 | Bohanec et al. | SalesLuv 현재 실험 |
|---|---|---|
| 데이터 행 | 원본 448 | 완전 동일 행 제거 후 365 |
| 입력 | 22개 | 22개 |
| 평가 분할 | 무작위 80/20, 30회 평균 | 고정 70/30, `random_state=1` |
| 모델 선택 | 논문 절차 | Train 내부 5-Fold CV Brier |
| 대표 모델 | Random Forest | LR+TabICL Soft Voting |

데이터 전처리, 분할 비율, 반복 횟수와 모델 선택 기준이 다르므로 두 수치만으로 모델의 우열을 단정하지 않는다.

## 9. 전체 재학습과 저장 검증

모델 선택과 평가가 끝난 뒤 `SoftVoting_LR_TabICL`과 같은 구성에 전체 365건으로 `fit`했다. 이 과정에서 LogisticRegression 파이프라인은 365건으로 다시 학습됐고, 사전학습 TabICLv2는 가중치를 미세조정하지 않고 365건을 추론 문맥으로 저장했다. 두 구성요소를 각각 저장하고, 두 확률을 1:1로 평균하는 규칙과 임계값을 JSON 메타데이터에 기록했다.

| 검증 항목 | 결과 |
|---|---|
| 원본 CSV SHA-256 | 메타데이터와 일치 |
| 두 모델 파일 SHA-256 | 메타데이터와 일치 |
| 새 오프라인 CPU 프로세스 로드 | 통과 |
| 기준 16건 재예측 | 통과 |

최대 확률 차이는 허용오차보다 작아 재로드 전후 예측 일치 검사를 통과했다. 이는 저장과 재로드가 정상이라는 증거이며, 모델의 외부 일반화 성능을 추가로 증명하는 검사는 아니다.

## 10. 한계와 위험

1. **외부 데이터 차이**: Salvirt 데이터는 SalesLuv 실제 국내 영업 데이터가 아니다.
2. **분할 한계**: 딜·고객사·담당자 그룹 또는 시간 분할을 적용하지 않았다.
3. **중복 판단 한계**: 고유 딜 ID가 없어 완전히 같은 행이 실제 같은 딜인지 확인할 수 없다.
4. **작은 표본**: 최종 정제 데이터가 365건이며 Test는 110건이다.
5. **Test 해석 한계**: 선택 코드는 CV Brier만 사용했지만 여러 후보의 Test 값이 비교표에 표시됐다. 완전히 독립된 외부검증으로 부르지 않는다.
6. **확률 보정 근거 제한**: Brier는 비교했지만 calibration curve, calibration intercept/slope와 별도 시계열 외부 검증은 수행하지 않았다.
7. **비용함수 부재**: 임계값 0.50은 금액 기반 FP/FN 비용 최적화 결과가 아니다.
8. **데이터 사용 조건**: Salvirt 공식 페이지는 공개 다운로드를 제공하지만 데이터셋의 명시적인 재배포·상업 이용 라이선스는 별도 확인이 필요하다.
9. **서비스 미연결**: 현재 백엔드는 10개 특성의 더미 모델을 사용하며 최종 22개 특성 모델과 연결되지 않았다.
10. **End-to-end 미검증**: 미팅 원문에서 22개 특성을 구조화하는 Agent의 추출 정확도와, 그 오류를 포함한 전체 성능은 아직 평가하지 않았다.
