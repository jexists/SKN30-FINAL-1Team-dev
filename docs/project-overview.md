## 1. 한 줄 정의

SalesLuv는 단순한 고객 데이터베이스가 아니라, **고객·딜·일정·미팅 기록·보고서를 연결하고 AI의 제안을 사람이 검토·승인해 다음 실행으로 잇는 Human-in-the-loop AI 영업 운영 CRM**입니다.

| 가치 제안 | 연결된 영업 기록 · 근거 기반 AI · 사람의 승인 · 실행 가능한 다음 행동 |
| 프로젝트 목표 | 영업 기록부터 보고와 후속 실행까지 이어지는 Human-in-the-loop 업무 흐름 구현 |

## 2. 문제 정의

B2B 영업의 핵심 자산인 고객 맥락과 영업 노하우는 담당자 개인에게 암묵지로 축적되지만 조직 자산으로 남지 않아, 이직·인수인계 시 관계와 노하우가 함께 소실됩니다.

| 문제 | 현장 상황 | 조직 영향 |
|---|---|---|
| 암묵지 소실 | 고객 맥락·상담 히스토리·영업 노하우가 담당자 머릿속과 개인 파일에만 존재 | 이직·퇴사 시 관계와 노하우 단절, 인수인계 손실 |
| 정보 분산 | 고객·상담·일정·문서가 CRM, 엑셀, 메신저, 캘린더에 분리 | 맥락 단절, 후임자 재파악 비용 증가 |
| 보고 중복 | 미팅 내용을 다시 정리해 일일·주간 보고에 반복 입력 | 영업 시간 감소, 누락·표현 편차 |
| 다음 행동 부재 | 기록은 남지만 후속 업무·계약 갱신·다음 일정이 연결되지 않음 | 기회 손실, 일정 지연 |
| 팀 현황 불투명 | 팀장이 일정·보고·매출·리스크를 수작업으로 재취합 | 코칭과 의사결정 지연 |

## 3. 시장 선정 근거

시장 전체보다, **처음 선택받을 수 있는 진입 시장**을 먼저 봅니다. 의료기기 영업 CRM으로 시작해 범용 B2B 영업 CRM으로 확장합니다.

작지만 고객과 구매 이유가 명확한 시작점입니다.

## 5. 차별화

### 5.1 핵심 기능 4가지

차별점은 "자동 입력" 하나가 아니라, 맥락을 모아 판단·승인·재계산하는 흐름입니다.

| | 기능 | 설명 |
|---|---|---|
| 01 | 통합 맥락 카드 | 고객·딜·활동·결정자·이슈를 한 화면에서 연결. 메일·캘린더·메신저 등 분산 정보를 이어 붙임 |
| 02 | 업무 보고서 초안 | STT·OCR·직접 입력을 바탕으로 보고서와 변경안 생성. 사람이 수정·확정하기 전에는 저장하지 않음 |
| 03 | 딜 × 포트폴리오 판단 | 딜 내부의 다음 행동과 딜 사이의 우선순위를 분리 판단. 충돌 시 제약을 되돌려 재분석 |
| 04 | 승인 게이트 | AI는 분석·준비·제안까지. CRM 변경·캘린더 등록·보고서 확정은 승인 후 반영 |

### 5.2 기존 도구와 비교

| 비교 항목 | 일반 CRM | 그룹웨어 | SalesLuv |
|---|---|---|---|
| 주요 목적 | 고객·실적 저장과 조회 | 일정·결재·문서 공유 | 영업 기록을 다음 실행으로 연결 |
| 업무 연결 | 기능별 데이터 조회 | 업무 공유 중심 | 고객 → 미팅 → 보고 → 계약·일정 폐쇄형 루프 |
| AI 방식 | 요약·생성 기능 단위 | 일반 문서 보조 | 근거가 있는 초안·추천·변경 후보 |
| 통제 | 사용자가 직접 입력 | 결재 절차 | 사람 승인 이후에만 기록과 일정 변경 |

## 6. 사용자 시나리오

영업 담당자는 추천을 받고 선택하며, 시스템은 승인된 정보로 다음 사이클을 다시 계산합니다.

| 단계 | 사용자 행동 | 시스템 결과 |
|---|---|---|
| 1. 오늘의 우선순위 | 담당자 또는 팀 범위로 대시보드에 진입 | 일정, 후속 지연, C/S, 갱신, 매출 목표를 우선순위로 표시 |
| 2. 미팅 전 브리핑 | 일정 상세에서 고객·계약·발주와 과거 기록 확인 | 미팅 목표, 확인 질문, 미완료 업무를 브리핑 |
| 3. 미팅 후 입력 | STT·OCR·직접 입력으로 미팅 내용 기록 | 미팅 결과와 활동 내역을 보고 작성 대상으로 연결 |
| 4. 보고서 확정 | AI 보고 내용을 확인·수정하고 첨부·활동을 선택해 제출 | 해당 일자의 업무보고와 검토 대기 상태 생성, 제출 이력 보존 |
| 5. 정보 반영 | 승인한 변경을 CRM에 반영 | 딜 판단과 전체 우선순위를 재계산 |
| 6. 팀장 검토·분석 | 조회 범위를 선택해 보고서를 확인하고 코멘트·검토 상태 반영 | 팀원 피드백과 확인·반려·수정 요청 결과 기록, 업무·매출 분석 제공 |

> 운영 원칙: AI는 분석·준비·초안·제안까지, 최종 확정은 사람의 선택과 승인으로.

| 일정관리<br>`schedule_management` | 전체 캘린더와 각 고객사의 미팅 제안을 종합해 충돌 없는 일정을 추천 | 일정 등록·수정·취소 · 현재 캘린더 · 각 고객사의 미팅 제안 | 다음 일정 추천 · 충돌 조정 결과 | 충돌 시 관련 고객사의 영업·계약관리를 호출해 변경 가능 여부나 대체 일정을 확인. 사용자가 수정·승인한 일정은 영업·계약관리로 돌아가 브리핑 생성의 입력이 됨 |
| 자료요약<br>`document_summary` | 자료실에 등록된 문서의 핵심 내용을 요약해 브리핑으로 제공 | PDF · PPTX · DOCX · HTML 등 문서 파일 | 자료요약 브리핑 | 영업·계약관리가 브리핑을 만들 때 RAG로 조회하는 대상. 그 밖에는 독립적으로 동작 |

### 7.2 동작상 주의점

- 계약가능성 분류용 구조화 값(ML 입력값)은 **ML 모델에만** 사용되며 보고서 작성이나 다른 에이전트에는 전달되지 않습니다.
- 보고서 작성은 미팅 분석의 전체 분석 결과를 받지 않습니다. **미팅 원문을 직접 참조하고 C/S 내용만 추가로 반영**합니다.
- 영업·계약관리는 **고객사 단위**로 담당합니다. 한 고객사에 계약이 여러 건일 수 있어, 그 고객사에 속한 딜·계약과 거기 연결된 보고서·미팅·후속 일정을 함께 관리합니다.
- 구조도의 `교류`는 일정 충돌 시 일정관리가 관련 고객사의 영업·계약관리에 대안을 묻고, 응답을 반영해 새 일정을 추천하는 과정입니다. 영업·계약관리는 자기 고객사만 판단하고 전체 일정은 일정관리가 확인합니다.
- 딜·계약 브리핑은 다음 미팅을 제안하는 시점이 아니라, 일정관리가 추천한 일정을 사용자가 수정·승인해 영업·계약관리로 돌아온 뒤에 만듭니다.
- 자료요약은 문서 처리 전용이지만, 영업·계약관리가 브리핑을 만들 때 그 요약 결과를 RAG로 조회해 근거로 씁니다. 요약은 참고 정보이므로 중요한 조건은 원본 문서와 함께 확인합니다.
- C/S 요청 등록, 보고서 확정처럼 업무에 반영되는 결과는 자동 확정하지 않고 **사용자 검토 후** 처리합니다.

### 7.3 실행·감사 원칙

| 원칙 | 적용 방식 |
|---|---|
| 권한 우선 | 모든 실행에서 요청자의 팀·역할·데이터 범위를 먼저 확인 |
| 근거 추적 | 참조 원천, 정제 입력, 출력, 근거, 모델·프롬프트 버전과 실행 상태 기록 |
| 호출 관계 | 상위·하위 실행 관계로 에이전트 간 교류와 결과 전달을 추적 |
| 안전한 확정 | 검증 실패·사용자 거절·실행 실패 시 확정 업무 데이터는 변경하지 않음 |
| 중복 방지 | 사용자 실행 요청에 멱등 키를 적용해 같은 작업의 중복 처리를 방지 |
| 최소 데이터 | 비밀번호·토큰·불필요한 개인정보와 권한 밖 원문을 입력·출력·근거에서 제외 |

| 영업현황 | 영업 단계별 목록·상세·수정·삭제와 고객·활동·견적·계약 연결 | 단계와 담당자 변경 및 연관 데이터가 일관되게 반영 |
| 견적·계약·발주 | 견적 템플릿·현황, 계약 목록·상세·필터, 발주 5단계와 상세·수정·삭제 | 문서·담당자·기간·금액·상태 전이와 첨부 연결 확인 |
| 매출분석 | 주·월·분기·반기·연도, 계약·지역·상품 기준 분석과 팀원 비교 | 기간·조회 범위별 집계와 목표 달성률이 일치 |
| 자료실 | 문서 목록·다운로드·AI 요약, 팀장 폴더·업로드·이동·이름 변경·삭제 | 파일 권한, 원문 근거, 폴더와 파일 변경 결과 확인 |
| 팀 관리 | 구성원 수, 직함·역할·재직 상태·월 매출 목표, 변경 취소·저장 | 팀장 권한과 저장·취소 결과가 지속적으로 유지 |

**MVP 완료 조건** — 팀원은 `대시보드 → 고객·일정 → AI 미팅·보고 → 영업 문서 → 자료 활용` 흐름을 수행하고, 팀장은 `조회 범위 선택 → 보고 검토 → 팀 영업·매출 조회 → 자료·구성원 관리`를 수행합니다. 모든 변경은 역할 권한과 승인 규칙에 따라 저장되어야 합니다.

### 단계적 확장 방향

C/S 처리 단계 통계, 미팅·후속 업무·C/S의 심화 연결, 매출 사후정산은 MVP 이후 고도화합니다. 외부 캘린더 연동과 네이티브 모바일 앱도 운영 검증 후 우선순위에 따라 확장합니다.

## 10. 성공 KPI와 리스크

### 10.1 파일럿 검증 원칙

대상 기능은 **승인형 AI 미팅보고 자동화**입니다. 동일 사용자·동일 보고 유형의 도입 전 2주를 기준선으로 삼고, 1주 적응 후 4주간 측정합니다. 30건 미만은 참고값으로 표시하며 아래 목표는 검증할 가설입니다. 품질 안전선은 **근거 없는 핵심 사실 오류 0건**입니다.

| 업무 개선 KPI | 측정 정의 | 파일럿 목표(가설) |
|---|---|---|
| 보고서 작성시간 | 편집 화면의 활성 작업시간 중앙값 | 기준 대비 40% 감소, 건당 10분 이내 |
| 당일 제출률 | 미팅 당일 23:59까지 제출한 보고서 ÷ 보고 대상 미팅 | 85% 이상 또는 기준 대비 20%p 향상 |
| 필수정보 초회 완성률 | 첫 제출 시 필수항목을 충족한 보고서 ÷ 제출 보고서 | 95% 이상 |
| 팀장 검토시간 | 검토 화면의 활성 작업시간 중앙값 | 기준 대비 30% 감소, 건당 5분 이내 |
| 후속 행동 연결률 | 담당자·기한이 있는 활동으로 연결된 승인 후속 행동 ÷ 전체 승인 후속 행동 | 90% 이상 |
