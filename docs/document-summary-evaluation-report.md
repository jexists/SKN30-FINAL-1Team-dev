# 문서요약 에이전트·RAG 1차 평가 결과보고서

작성일: 2026-09-15

## 1. 결론

[검증] 견적서·계약서·발주서·상품설명서 각 3개씩, 총 12개 문서를 대상으로 문서요약 12건과 RAG 질의 12건을 생성·평가했다.

[검증] LLM-as-a-Judge 전체 Overall은 기존 0.6708에서 재실행 후 0.7600으로 0.0892 상승했다. 다만 사람검수 상태는 아직 `pending`이다.

[추론] 현재 우선 개선 대상은 계약서 요약과 상품설명서 RAG다. 발주서 요약도 공급자·납품·결제조건 보존 여부를 추가 확인해야 한다.

## 2. 테스트 범위와 방법

| 항목 | 내용 |
|---|---|
| 입력 | [검증] `data/sample`의 4개 유형 각 3개 PDF |
| 대상 문서 | [검증] 견적서 3개, 계약서 3개, 발주서 3개, 상품설명서 3개 |
| 골든셋 | [검증] RAGEval 적응형 schema summary → QRA 흐름으로 summary/RAG 케이스 생성 |
| 정답 보강 | [검증] 견적서·계약서·발주서 정답지 XLSX 9개 반영 |
| 상품설명서 기준값 | [검증] 전용 정답지가 없어 LLM 생성 기준값 사용; 사람검수 필요 |
| 평가 | [검증] LLM-as-a-Judge로 completeness, hallucination, irrelevance, groundedness, retrieval relevance, overall 평가 |
| 검색 구현 | [검증] 현재 평가 스크립트의 로컬 키워드 검색기; 운영 벡터 검색 성능과 동일하다고 볼 수 없음 |
| OCR | [검증] 텍스트 추출 실패 문서는 설정된 OCR provider로 fallback |

참고 방법론: [RAGEval 논문](https://aclanthology.org/2025.acl-long.418/), [Langfuse LLM-as-a-Judge](https://langfuse.com/docs/evaluation/evaluation-methods/llm-as-a-judge), [Langfuse Evaluation Overview](https://langfuse.com/docs/evaluation/overview)

## 3. 전체 평가 결과

[검증] 재실행 결과는 24개 케이스 모두 생성·평가되었고, RAG 검색 문맥이 비어 있는 케이스는 5건에서 0건으로 감소했다.

| 지표 | 재실행 결과 | 기존 대비 변화 |
|---|---:|---:|
| Overall | 0.7600 | +0.0892 |
| Completeness | 0.7421 | +0.1017 |
| Hallucination 품질점수 | 0.8775 | +0.0521 |
| Irrelevance 품질점수 | 0.8529 | +0.0308 |
| Groundedness | 0.8325 | +0.1067 |
| Retrieval relevance | 0.8671 | +0.1117 |

[검증] 위 점수는 LLM Judge 점수이며, 사전에 확정된 사람검수 합격 기준은 현재 없다. 따라서 0.7600을 최종 합격률로 해석하지 않는다.

## 4. 유형별 결과

[검증] 아래 Overall은 유형별 3개 케이스 평균이다.

| 문서 유형 | 요약 Overall | RAG Overall | 해석 우선순위 |
|---|---:|---:|---|
| 견적서 | 0.9233 | 1.0000 | 상대적으로 안정적 |
| 계약서 | 0.3400 | 1.0000 | 요약 개선 최우선 |
| 발주서 | 0.6400 | 0.8500 | 요약 필드 보존 확인 필요 |
| 상품설명서 | 0.8767 | 0.4500 | RAG 질의·검색 개선 최우선 |

[추론] 계약서 RAG가 1.0000인 것은 현재 3개 샘플의 질의와 검색 문맥에서 평가된 결과다. 계약서 전체 품질이 확보되었다는 일반화는 표본 수가 작아 할 수 없다.

## 5. 결과가 낮거나 추가 검토가 필요한 케이스

### 5.1 문서요약

#### 계약서 3건

| 케이스 | Overall | 주요 문제 |
|---|---:|---|
| 계약서_2 | 0.2400 | [검증] 계약 당사자·대표 관계, 작성일·공급일, VAT 포함 총액을 누락하거나 납기 정보가 없다고 잘못 기재 |
| 계약서_1 | 0.3800 | [검증] 당사자·대표자·주소·작성일·공급일 누락; 계약금과 잔금을 VAT로 잘못 해석 |
| 계약서_3 | 0.4000 | [검증] 당사자·대표자·작성일·공급일·VAT 포함 총액을 누락하거나 불명확하다고 서술 |

[추론] 공통 원인은 OCR 손상 가능성이 있는 계약서에서 확인 가능한 필드까지 보수적으로 `확인 불가` 처리하고, 금액 필드의 의미를 구분하지 못한 것이다.

#### 발주서

| 케이스 | Overall | 주요 문제 |
|---|---:|---|
| 발주서_1 | 0.3600 | [검증] 공급자·발주자 역할을 뒤바꾸고, 공급자 정보·납품장소·대금 지급조건을 누락 |
| 발주서_2 | 0.7800 | [검증] 공급자·납품장소·대금 지급조건을 누락하고 결제조건이 없다고 표시 |
| 발주서_3 | 0.7800 | [검증] 공급자와 결제조건을 명시적으로 식별하지 못했고 OCR 오류 형태의 주소가 남음 |

[추론] 발주서는 `발주자`와 `공급자`의 역할 분리, `납품장소`, `대금 지급조건`을 별도 필드로 강제하는 구조화 출력이 필요하다.

#### 상대적으로 높은 점수지만 공통적으로 남은 문제

[검증] 견적서와 상품설명서 요약은 상대적으로 높았지만, 일부 결과에 `sales_relevance`, `risk_flags`, 후속 협의 권고 등 요청 범위를 넘어선 영업적 해석이 포함되었다.

[추론] 문서요약 모드와 영업 인사이트 모드를 출력 스키마·프롬프트에서 분리해야 요약 정확도와 불필요한 내용 억제를 동시에 관리할 수 있다.

## 7. 리스크와 한계

[검증] 표본은 유형별 3개이므로 전체 50개 문서군의 성능으로 일반화할 수 없다.

[검증] 상품설명서에는 전용 정답지가 없어 현재 점수의 기준값 품질이 사람검수로 확정되지 않았다.

[검증] OCR fallback 5건이 포함되었으므로 OCR 오류와 요약 Agent 오류를 분리해 분석해야 한다.

[검증] 현재 RAG 결과는 평가 스크립트의 로컬 키워드 검색 결과이며, 실제 서비스의 임베딩·reranker·chunk 설정과 다를 수 있다.

[추론] 사람검수에서 `수정 필요`가 발생한 케이스는 골든셋에 반영한 뒤 Judge를 재실행해야 모델 개선 전후를 공정하게 비교할 수 있다.
