# 시스템 구성도 작성 프롬프트

아래 내용을 프로젝트 루트에서 실행하는 분석 에이전트에게 전달한다. 제출 템플릿 PDF도 함께 전달한다.

````text
SalesLuv 프로젝트의 제출용 「AI 시스템 아키텍처 (멀티 에이전트 아키텍처)」 문서를 만든다.

## 작업 순서

1. 코드를 확인한다.
2. 확실하지 않은 내용은 사용자에게 먼저 질문한다.
3. 답변을 받은 뒤 Markdown과 그림을 만든다.
4. 사용자가 Markdown을 보고 `오케이`라고 답한 뒤에만 PDF를 만든다.

Markdown을 확인받기 전에는 PDF를 만들지 않는다. PDF에는 `검토 중`, `확인 필요`, `초안`, `미확인`, 질문, 빈칸 같은 문구를 절대 넣지 않는다.

## 코드 기준과 질문

- `frontend`, `backend`, `infra`, `deploy`, `.github`, 의존성 파일을 읽고 **현재 코드와 설정**을 기준으로 쓴다.
- README와 기존 문서는 참고 자료다. 코드와 다르면 코드 기준으로 판단한다.
- 코드에서 확정할 수 없는 것은 추측해서 쓰지 않는다.
- 확실하지 않은 내용이 하나라도 있으면 Markdown이나 그림을 만들기 전에 먼저 질문하고 답변을 기다린다.
- 질문할 내용: 실제 운영 서버, AWS 운영 여부, 실제 AI 모델, Runpod 사용 여부, Supabase 사용 범위, 사람 승인 절차, 코드와 문서가 다를 때 제출 기준.
- 질문은 짧고 구체적으로 쓴다. 예: `배포 문서에는 AWS가 있지만 현재 운영 중인지는 코드만으로 알 수 없습니다. 제출 그림에 AWS를 넣을까요?`
- 비밀번호, API 키, 고객 정보, 비밀 주소는 문서·그림·PDF에 넣지 않는다.

답변 전에는 아래 내용만 보여 준다.

1. 코드에서 확인한 내용
2. 사용자에게 확인할 질문

## 기존 그림 사용

기존 멀티 에이전트 구성도는 아래 파일이다.

`docs/technical/multiagent/multiagent-flow.png`

이 그림을 2번 “멀티 에이전트 아키텍처”의 기준 그림으로 사용한다. 그림의 에이전트, 입력, 출력, 사람 승인 흐름을 코드와 대조한다.

- 코드와 같은 내용은 유지한다.
- 코드와 다른 내용은 사용자에게 먼저 질문한 뒤 고친다.
- 원본 `multiagent-flow.png`는 덮어쓰지 않는다.
- 제출용 그림이 필요하면 수정본을 `multiagent-architecture.png`와 `multiagent-architecture.svg`로 새로 만든다.
- Markdown에는 최종 그림을 넣는다.

```md
![SalesLuv 멀티 에이전트 아키텍처](multiagent-architecture.png)
```

## 글쓰기 방식

- 사람에게 설명하듯 짧고 자연스럽게 쓴다.
- 어려운 말보다 쉬운 말을 쓴다. 필요한 기술 이름만 괄호 안에 한 번 쓴다.
  - 예: `웹 화면 (React)`, `API 서버 (FastAPI)`, `데이터베이스 (Supabase)`
- 그림 속 이름은 짧은 명사형으로 쓴다.
  - 예: `사용자`, `웹 화면`, `API 서버`, `미팅 분석`, `보고서 작성`, `계약 관리`, `일정 관리`, `자료 요약`, `데이터베이스`, `파일 저장소`
- 홍보 문구나 AI가 만든 듯한 과장 표현은 쓰지 않는다.
  - 쓰지 않는 말: `혁신적`, `강력한`, `최첨단`, `완벽한`, `차세대`
- 코드로 확인한 내용만 문장으로 쓴다.

## 그림 제작과 확인

- 기존 그림을 기준으로 SVG와 PNG 수정본을 만든다. 생성형 이미지로 글자나 상자를 만들지 않는다.
- PNG는 가로형 16:9, 최소 1600×900px으로 만든다.
- 글자는 최소 16px, 제목은 24px 이상으로 한다.
- 한글이 깨지지 않는 글꼴을 쓴다.
- 상자, 글자, 화살표가 겹치지 않게 한다.
- 화살표가 글자 위를 지나가지 않게 한다.
- 한 상자에는 짧은 이름과 설명 한 줄만 넣는다.
- PNG를 직접 열어 글씨 크기, 한글 깨짐, 겹침, 잘림을 확인한다. 문제가 있으면 고쳐서 다시 만든다.

## PDF 만들기

사용자가 Markdown과 그림을 보고 `오케이`라고 답한 뒤에만 PDF를 만든다.

PDF는 제출용 최종본이다. 사용자의 답변으로 확정한 내용과 코드에서 확인한 내용만 넣는다. `검토 중`, `확인 필요`, `초안`, `미확인`, 질문, 내부 작업 설명은 넣지 않는다.

PDF를 만든 뒤에는 모든 페이지를 이미지로 확인한다. 글씨가 작거나, 한글이 깨지거나, 표·그림·화살표가 겹치거나, 잘린 곳이 있으면 수정 후 다시 만든다.
````
