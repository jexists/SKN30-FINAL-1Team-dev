# 브리핑 자료 RAG 최소 테스트 세트

> 화면에서 무엇을 누르는지는 `RUNBOOK.md`, 결과 기록은 `TEST_CHECKLIST.md`.

미팅 상세의 📦 제품 자료 / 📎 관련 자료 / RAG 검색 근거 표시를 손으로 확인하기 위한
최소 구성 테스트 데이터다. 모두 가상 데이터이며 실제 고객·영업 정보는 들어 있지 않다.

## 2. 문서 등록 순서와 연결 대상

브리핑 생성 **전에** 1~5번을 올리고, 6번은 브리핑을 한 번 만든 **뒤에** 올린다.

| 순서 | 파일 | 연결 대상 | 확인 목적 |
| --- | --- | --- | --- |
| 1 | `01_초음파진단기_제품자료.txt` | 제품 `SLV-LITE-100 초음파 진단기` | 📦 제품 자료 표시 |
| 2 | `02_이동형카트_제품자료.txt` | 제품 `SLV-CART-20 이동형 카트` | 견적 품목 제품의 자료 표시 |
| 3 | `03_초음파도입_납품계약서.pdf` | 딜 `테스트병원 초음파 도입 딜` | 📎 관련 자료 + 페이지·인용 표시 |
| 4 | `04_같은고객사_설치점검.txt` | 딜 `테스트병원 유지보수 딜` | 고객사 범위 RAG 검색 |
| 5 | `05_다른고객사_제외자료.txt` | 딜 `무관 테스트의원 장비 도입 딜` | 같은 키워드라도 검색 제외 |
| 6 | `06_브리핑생성후_추가자료.txt` | 딜 `테스트병원 초음파 도입 딜` | 브리핑 생성 후 자동 갱신 |
| 7 (선택) | `07_다른담당자_비공개자료.txt` | 딜 `테스트병원 초음파 도입 딜`, **같은 팀의 다른 일반 담당자 계정으로 등록** | 문서 열람 권한 |

각 문서를 올린 뒤 처리 상태가 `완료(completed)` 가 될 때까지 기다린다. 처리 중인 파일은
검색 근거와 자료 목록 양쪽에서 모두 빠진다.

## 3. 문서별 심어 둔 키워드

| 파일 | 220V | 90cm | BLUE-731 | 대금 지급 조건 |
| --- | --- | --- | --- | --- |
| 01 제품자료(진단기) | O | - | - | - |
| 02 제품자료(카트) | O | O | - | - |
| 03 납품계약서 PDF | O (1p) | O (1p) | **O (2p만)** | **O (2p)** |
| 04 같은 고객사 설치점검 | O | O | - | - |
| 05 다른 고객사 자료 | O | O | O | - |
| 06 브리핑 후 추가자료 | O | - | O | - |
| 07 다른 담당자 자료 | O | - | O | - |

- `BLUE-731` 은 계약서 **2페이지에만** 있다. 인용에 붙은 페이지가 2인지로 페이지 표시를 검증한다.
- 05번은 04번과 키워드가 겹치게 써 뒀다. 그런데도 검색 근거에 나오면 고객사 범위 필터가 깨진 것이다.

## 4. 테스트 절차

1. 제품 2개, 고객사 2개, 딜 3개를 등록한다.
2. 현재 딜에 대표 제품(SLV-LITE-100)과 견적 품목(SLV-CART-20)을 연결한다.
3. 문서 1~5를 위 표대로 업로드한다.
4. 모든 문서의 처리 상태가 완료가 될 때까지 기다린다.
5. 위 일정을 만들고 딜·고객 담당자를 연결한다.
6. 미팅 상세를 열고 브리핑을 생성한다.
7. `TEST_CHECKLIST.md` 의 항목을 확인한다.
8. 문서 6을 올리고 백그라운드 자동 갱신으로 반영되는지 본다 (수동 새로고침 버튼은 없다).
9. (선택) 다른 담당자 계정으로 문서 7을 올려 권한을 확인한다.

## 5. 정리

테스트가 끝나면 문서 → 딜 → 고객사 → 제품 순으로 지운다. 문서가 남은 상태에서 딜을 먼저
지우면 연결이 끊긴 자료가 남는다.

## 6. 레이저장비 제품 자료 (11~13) — 이미지 PDF

위 1~5는 초음파 시나리오다. 11~13은 별개로, **스캔 계약서에서 OCR 이 표를 지키는지**
보려고 만든 레이저장비 제품 자료다. 실제 계약서 샘플(`data/sample/계약서_50개`)이 전부
글자가 이미지로만 든 스캔 PDF 라, 같은 조건을 재현한다.

| 파일 | 연결 대상 | 형식 |
| --- | --- | --- |
| `11_LP1000_제품자료_이미지.pdf` | 제품 `LP1000` | **이미지 PDF** (텍스트 레이어 없음 → OCR) |
| `12_LP1500_제품자료_이미지.pdf` | 제품 `LP1500` | **이미지 PDF** |
| `13_LR-CORE2_제품자료_이미지.pdf` | 제품 `LR-CORE2` | **이미지 PDF** |

`10_LR2000_제품자료_테스트.pdf` 는 텍스트 레이어가 있는 PDF 다. 10 과 11~13 을 견주면
같은 화면에서 **OCR 을 탄 자료와 안 탄 자료의 차이**가 그대로 드러난다.

### 심어 둔 값

계약서 샘플의 품목 단가와 일부러 맞췄다. 브리핑이 수량과 단가를 대조할 수 있다.

| 모델 | 기준 단가 | 계약서에서 | 그 밖의 확인용 값 |
| --- | --- | --- | --- |
| LP1000 | 130,000 | 4개 520,000 | 파장 755nm, 교체 12,000샷, 보증 6개월 |
| LP1500 | 145,000 | 4개 580,000 | 스팟 6mm, 교체 15,000샷, 납기 15영업일 |
| LR-CORE2 | 4,800,000 | 2개 9,600,000 | 소비전력 1,450W, 설치 380x520mm, 보증 36개월 |

각 파일에는 계약서와 같은 **격자 표**가 한 개씩 들어 있다. OCR 이 행·열을 지키지 못하면
단가가 엉뚱한 항목에 붙거나 통째로 빠지므로, 그 표가 곧 판정 기준이다.

### 확인할 것

- 세 자료의 처리 상태가 `완료` 인가 (OCR 제공자가 꺼져 있으면 여기서 멈춘다)
- 브리핑이 **단가를 제 모델에 붙여** 말하는가 (`LR-CORE2 4,800,000`)
- 설치 조건(전원 220V, 공간 380x520mm)이 첫 미팅 확인 항목으로 올라오는가
- 읽지 못한 값을 나열하거나 "OCR" 같은 처리 용어를 본문에 쓰지 않는가

### 주의

제품 자료에는 고객사 이름을 넣지 않았다. 제품 자료는 고객사와 무관해야 하며, 특정 딜에
묶어 올리면 다른 고객사 브리핑까지 딸려 들어갈 수 있다. **제품에만 연결한다.**
